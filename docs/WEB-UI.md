# Web UI (S12) — หน้าจอที่ daemon เสิร์ฟเอง

> เขียน 2026-08-31 · API ที่มันคุยด้วยอยู่ที่ [`HTTP-API.md`](HTTP-API.md)
> รีโปอ้างอิงอยู่ที่ [`ARCHITECTURE.md` §7](ARCHITECTURE.md)

```bash
RcloneBrowser.exe --daemon
```

แล้วเปิด **http://127.0.0.1:19999/** วาง token ที่ daemon พิมพ์ออกมา — จบ

## หน้าต่างกับหน้าเว็บ เปิดพร้อมกันได้

**เปิดโปรแกรมตามปกติก็มีหน้าเว็บด้วย** ไม่ต้องใช้ `--daemon` · เมนู **Help → Open web interface…**
บอกที่อยู่และคัดลอก token ให้

ทั้งสองเป็น**หน้าจอของ core ตัวเดียวกันใน process เดียวกัน** ไม่มีตัวไหนเป็นคนทำงาน:
กด Run ในหน้าเว็บ การ์ดงานขึ้นในหน้าต่าง · หยุดคิวในหน้าต่าง ปุ่มในหน้าเว็บเปลี่ยนตาม
เพราะทั้งคู่ฟังสัญญาณชุดเดียวกันจาก `JobRegistry` · `JobQueue` · `AppCore`
ไม่ได้คุยกันเอง

| เปิดแบบไหน | ได้อะไร |
|---|---|
| `RcloneBrowser.exe` | core + หน้าต่าง + หน้าเว็บ |
| `RcloneBrowser.exe --daemon` | core + หน้าเว็บ |

**เปิดได้ทีละตัวเท่านั้น** หน้าต่างกับ daemon จับ lock ไฟล์เดียวกัน — ตัวที่สองจะบอกว่ามีตัวรันอยู่แล้ว
(`--daemon` ออกด้วยรหัส 75) · เดิม daemon ไม่จับ lock เลย เปิดซ้อนกันแล้วได้สองนาฬิกาสองคิว
บนฐานข้อมูลเดียว ตารางเวลาที่ถึงกำหนดจะยิงสองครั้ง

ปิดหน้าเว็บได้ด้วย `Settings/apiEnabled=false`

## ทำไมไม่เอา Web UI ของ rclone มาใช้

แผนเดิมให้ประเมินก่อนว่าเสิร์ฟ [`rclone-web`](https://github.com/rclone/rclone-web)
หรือ [`rclone-webui-react`](https://github.com/rclone/rclone-webui-react) ควบไปกับ API ของเรา
จะคุ้มกว่าเขียนเองไหม **คำตอบคือไม่** ด้วยเหตุผลเดียว:

**ทั้งสองตัวคุยกับ rc API ของ rclone** ซึ่ง**ไม่มีคิว ไม่มี task ที่บันทึกไว้ ไม่มีตารางเวลา
ไม่มีประวัติ** — ซึ่งคือทุกอย่างที่โปรแกรมนี้เป็น สิ่งที่มันแสดงได้คือ browse กับ transfer
ซึ่งเป็นของ rclone อยู่แล้ว ส่วนหน้าจอที่เราต้องการจริงๆ ต้องเขียนเองทั้งหมดอยู่ดี

แถมยังต้องแลกด้วย: npm + Vite ใน build, `rclone rcd` เป็น process ที่สอง, และ asset
อีกกองในอิมเมจ **เพื่อให้ได้หน้าที่ไม่มีของที่เราอยากโชว์**

จึงเขียนเอง — **ไม่มี build step ไม่มี framework ไม่มีคำขอออกไปนอก daemon**
สามไฟล์ (`index.html` · `app.css` · `app.js`) อยู่ใน `webui.qrc` **ที่ถูกคอมไพล์เข้าไปในตัว binary**
อิมเมจ Docker จึงมีแค่ binary กับ browser ที่อีกฝั่ง

## หน้าที่มี

| แท็บ | ทำอะไรได้ |
|---|---|
| **Jobs** | งานที่วิ่งอยู่ · หลอดความคืบหน้า · ไบต์/ไฟล์/error/เวลา · **Stop** · **Log** |
| **Queue** | ลำดับคิว · ตัวที่กำลังรัน · เอาออกจากคิว |
| **Tasks** | task ที่บันทึกไว้ · **Run** · **Queue** · **Dry run** |
| **Schedules** | ตารางเวลา · ครั้งถัดไป · **Run now** |
| **Remotes** | **รายชื่อรีโหมด + เดินดูไฟล์** — โฟลเดอร์/ขนาด/เวลาแก้ไข · breadcrumb กลับขึ้นได้ |
| **History** | ประวัติ · ใครสั่ง (`task`/`queue`/`scheduler`/`api`) · **Log** ของงานที่จบไปแล้ว |

ปุ่มบนหัว: **เดิน/หยุดคิว** · **Light/Dark** · **Password** · **Sign out**
จุดกลมข้างชื่อ = สายเหตุการณ์สดต่ออยู่หรือไม่

## เข้าระบบ

**ครั้งแรกไม่มีรหัสผ่าน** — ใช้ token ที่ daemon พิมพ์ออกมา แล้วหน้าเว็บจะขึ้นแถบเสนอให้ตั้ง
รหัสผ่าน **เสนอ ไม่ใช่บังคับ** เพราะเครื่องที่ไม่มีใครอื่นเข้าถึงได้ก็มีสิทธิ์ไม่ต้องมีรหัสผ่าน

ตั้งแล้วจะเข้าด้วย **user + password** ได้ (`admin` เปลี่ยนได้ที่ `Settings/apiUser`)
รายละเอียดการเก็บรหัสผ่านและการกันเดา อยู่ใน [`HTTP-API.md`](HTTP-API.md)

**token ยังใช้ได้เสมอ** — ปุ่ม *Use the token instead* มีไว้สำหรับตอนลืมรหัสผ่าน

## ธีมสว่าง

ปุ่ม **Light/Dark** สลับได้ และจำไว้ที่ browser · ถ้ายังไม่เคยเลือก จะ**ตามเครื่อง**
(`prefers-color-scheme`) — คนที่ตั้งเดสก์ท็อปเป็นสีสว่างไม่ได้ขอหน้าจอมืด

สีถูกตั้งชื่อไว้ที่เดียว ธีมสว่างจึงเป็น**หน้าเดิมที่ค่าต่างกัน** ไม่ใช่กฎชุดที่สองที่จะค่อยๆ เพี้ยนจากกัน

## เรื่องที่ตัดสินใจไว้ และเหตุผล

**token อยู่ใน header เท่านั้น ไม่เคยอยู่ใน URL** — URL ไปโผล่ใน log ของ proxy
ใน history ของ browser และใน `Referer` ของทุกลิงก์ที่หน้านั้นชี้ออกไป

**อ่าน SSE ด้วย `fetch()` ไม่ใช่ `EventSource`** — `EventSource` ส่ง header ไม่ได้
ทางเลือกเดียวของมันคือรับ token ทาง query string ซึ่งก็คือเอา token ไปไว้ใน URL อยู่ดี

**ไฟล์ของหน้าเว็บเสิร์ฟโดยไม่ต้องมี token** — มันคือ markup กับ script ที่ไม่ได้บอกอะไร
เกี่ยวกับเครื่องนี้เลย และหน้าที่มันสร้างก็ถามอะไร daemon ไม่ได้จนกว่าจะมีคนพิมพ์ token ลงไป
**หน้า login ที่ต้อง login ก่อนถึงจะเปิดได้ คือหน้าที่ไม่มีใครเปิดได้**

**สามไฟล์เป็นรายชื่อตายตัว ไม่ใช่โฟลเดอร์** — อะไรก็ตามที่แปลง path จากข้างนอกเป็นชื่อไฟล์
คือช่องให้อ่านไฟล์ที่ไม่ได้ตั้งใจจะเสิร์ฟ และที่นี่ไม่จำเป็นต้องมี เพราะมีสามไฟล์และรู้ชื่อตั้งแต่ตอนคอมไพล์

**คำปฏิเสธของ API ถูกเอามาแสดง ไม่ใช่กลืนหาย** — "that task is already running",
"its last run has not finished" มาจาก daemon ตรงๆ **นี่คือความต่างทั้งหมดระหว่างอันนี้กับ UI
ที่กดแล้วไม่มีอะไรเกิดขึ้นและไม่มีใครรู้ว่าทำไม**

**สายที่ขาดต่อกลับเอง** — โน้ตบุ๊กที่หลับไปตื่นมาเจอ socket ตาย dashboard ที่ต้อง refresh
ทุกครั้งที่กลับมาคือ dashboard ที่ไม่มีใครเปิดค้างไว้

## การเดินดูไฟล์ ต่างจากทุก endpoint อื่น

ทุก route ตอบทันทีจากของที่ถืออยู่แล้ว **แต่ `ls` ต้องรัน rclone แล้วรอ**
มันจึง**ถือ socket ไว้แล้วเขียนตอนคำตอบมาถึง** เหมือนที่สายเหตุการณ์ทำ

- **คนถามหายไป = rclone หยุด** ปิดแท็บหรือเน็ตหลุดแล้วยังอ่านไดเรกทอรีต่อให้คนที่ไม่อยู่แล้ว คือการเผาเครื่องเปล่าๆ
- **เกิน 20,000 รายการแล้วหยุด** พร้อมธง `truncated` — โฟลเดอร์แสนรายการจะถูกเก็บในหน่วยความจำสองชุด
  แล้วส่งลง socket ที่ไม่มีใครอ่านไหว
- **มีเส้นตายสองนาที** เป็นตัวกันพลาด ไม่ใช่ชิ้นส่วนที่ทำงานปกติ — ทุกทางข้างบนตอบเองอยู่แล้ว
  อันนี้มีไว้เพื่อไม่ให้ทางที่ยังไม่มีใครคิดถึงทำให้คนรอค้างตลอดกาล **ซึ่งคือสิ่งที่เกิดขึ้นจริงรอบแรก**
- **เปิดไม่ได้ต้องบอกว่าทำไม** — เดิมโฟลเดอร์ที่เปิดไม่ได้แสดงเป็นรายการว่าง
  ซึ่งอ่านได้ว่า "ในนี้ไม่มีอะไร" **ซึ่งเป็นคนละเรื่องกันเลย** ตอนนี้เหตุผลจาก rclone ขึ้นตรงที่ที่ไฟล์ควรอยู่

**บั๊กที่ผู้ใช้เจอในนาทีแรกที่เปิดใช้:** โฟลเดอร์ที่มี **7,103 ไฟล์** ค้างที่คำว่า *reading…* ตลอดไป

เพราะรอบแรกตอบจาก `finished()` ทางเดียว ส่วนทางที่ **"เกินจำนวนที่ขอ"** ไปเรียก `cancel()`
ซึ่ง**ตามการออกแบบแล้วมันเงียบสนิท** — request จึงไม่เคยถูกตอบเลย และ**ไม่มีอะไรใน log สักบรรทัด
เพราะไม่มีอะไรผิดพลาด มีแต่สิ่งที่ไม่ได้เกิดขึ้น**

ตอนนี้ทุกทางออกไปผ่าน `respond()` ตัวเดียวที่ตอบได้ครั้งเดียว และมี `fake_rclone` ใน test
ไว้สร้างโฟลเดอร์ที่ใหญ่เกินลิมิตได้ — บั๊กแบบนี้ต้องมีโฟลเดอร์ใหญ่กว่าลิมิตถึงจะโผล่

**เจอบั๊กอีกตัวตอนทำข้อนี้:** `RemoteRegistry::refresh()` ถูกเรียกจากหน้าต่างที่เดียว
daemon จึง**ไม่รู้จักรีโหมดสักตัว** — `/api/v1/remotes` ตอบว่าง และหน้า Remotes จะว่างเปล่าตลอดกาล
รูปเดียวกับบั๊กสคริปต์: **ความสามารถย้ายมาแล้ว แต่สายไฟยังไม่ได้ต่อ** · ย้ายไป `AppCore::start()` แล้ว

## ที่ยังไม่มี

- **สั่ง transfer จากหน้าเดินดูไฟล์** — ตอนนี้ดูได้อย่างเดียว
- **สร้าง/แก้ task** — API ยังไม่ให้ ด้วยเหตุผลใน [`HTTP-API.md`](HTTP-API.md)
- **หลายภาษา** — ตอนนี้อังกฤษล้วน เหมือนตัวหน้าต่าง
