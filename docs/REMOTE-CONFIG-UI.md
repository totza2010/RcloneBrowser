# แผน: ตั้งค่า remote ในโปรแกรม แทนการเปิดเทอร์มินัล

> เขียน 2026-08-26 · **R1 และ R2 (อ่านอย่างเดียว) ทำแล้ว 2026-10-19 — ดู "ทำแล้ว" ท้ายไฟล์** · เกี่ยวข้องกับ [`LAYER-SPLIT.md`](LAYER-SPLIT.md) บล็อก 2
> และ [`RCLONE-MANAGER.md`](RCLONE-MANAGER.md)

## ตอนนี้เป็นยังไง

ปุ่ม Config เปิด `rclone config` ในเทอร์มินัล แล้วโปรแกรมรอจนกว่าจะปิด ค่อยไปถามรายชื่อ
remote ใหม่ (ทดสอบแล้วใน V-24 ข้อ 2.2 — เพิ่ม remote แล้วโปรแกรมเห็นทันที)

**ใช้งานได้จริงและไม่พัง** แต่มีข้อจำกัดที่แก้ด้วยการปรับเล็กๆ ไม่ได้:

- **เป็นเมนูตัวเลขในเทอร์มินัล** คนที่ไม่คุ้นจะไม่รู้ว่าต้องกด `n` แล้วพิมพ์ชื่อ backend
- **โปรแกรมมองไม่เห็นอะไรเลยระหว่างนั้น** — ไม่รู้ว่ากำลังสร้าง แก้ หรือลบ
  รู้แค่ว่า "จบแล้ว ไปนับใหม่"
- **บนเครื่องที่ไม่มีเทอร์มินัล ทำไม่ได้เลย** ซึ่งรวมถึงโหมด daemon และ Web UI
  ที่เป็นเป้าหมายปลายทางทั้งหมดของงานนี้

ข้อสุดท้ายคือข้อที่ทำให้เรื่องนี้ต้องอยู่ในแผน ไม่ใช่ของเล่นเสริม

## สิ่งที่ทำให้เป็นไปได้ — rclone อธิบายตัวเองเป็นข้อมูล

```
rclone config providers      # JSON ของทุก backend และทุกตัวเลือก
```

บนเครื่องนี้ให้ **69 provider** และ teldrive ก็อยู่ในนั้นด้วย **13 ตัวเลือก**
แต่ละตัวเลือกบอกครบว่า `Required` · `IsPassword` · `Advanced` · `Default` · `Examples`

**แปลว่าฟอร์มไม่ต้องเขียนมือทีละ backend — สร้างจาก JSON ได้** ซึ่งเป็นจุดที่ทำให้
งานนี้เปลี่ยนจาก "เขียน 69 ฟอร์ม" เป็น "เขียนตัวสร้างฟอร์มหนึ่งตัว"

และสำคัญไม่แพ้กัน: **fork ที่เพิ่ม backend ใหม่จะโผล่มาเองโดยไม่ต้องแก้โปรแกรม**
ซึ่งตรงกับเหตุผลที่โปรเจกต์นี้มีอยู่

คำสั่งที่ใช้ได้แบบไม่ต้องโต้ตอบ:

| คำสั่ง | ใช้ทำ |
|---|---|
| `config providers` | รายการ backend + ตัวเลือก (JSON) |
| `config dump` | config ปัจจุบันทั้งไฟล์ (JSON) |
| `config create <ชื่อ> <type> k=v ...` | สร้าง |
| `config update <ชื่อ> k=v ...` | แก้ |
| `config delete <ชื่อ>` | ลบ |
| `config password <ชื่อ> k=v` | ตั้งรหัสผ่านในฟิลด์ที่เป็นรหัส |
| `config redacted` | อ่าน config โดยปิดบังความลับ — สำหรับแสดง |

## แบ่งเป็นขั้น

| ขั้น | ทำอะไร | ได้อะไร |
|---|---|---|
| **R1** | `RcloneConfig` (L1) — อ่าน providers และ dump เป็นข้อมูล | โปรแกรมรู้ว่ามี backend อะไร มีตัวเลือกอะไร |
| **R2** | หน้าจอดู remote: ชื่อ · ชนิด · ตัวเลือก (ปิดบังความลับ) | เห็นว่ามีอะไรอยู่โดยไม่ต้องเปิดเทอร์มินัล |
| **R3** | ลบ · เปลี่ยนชื่อ | งานที่ปลอดภัยและง่ายที่สุดก่อน |
| **R4** | สร้าง/แก้ backend ที่ไม่ต้อง OAuth (sftp, s3, teldrive, local…) | ครอบคลุมกรณีส่วนใหญ่ |
| **R5** | OAuth (drive, onedrive, dropbox…) | ครบ |

**R1 มีประโยชน์ทันทีแม้ไม่ทำ R2** เพราะ `RcloneFlagRegistry` กับ `RcloneCapabilities`
ที่มีอยู่แล้วเดาความสามารถของ backend จากชื่อ ถ้ามี providers เป็นข้อมูลจริง
ก็เลิกเดาได้

**R4 คือขั้นที่คุ้มที่สุด** — teldrive ซึ่งเป็นเหตุผลหลักของ fork นี้ ใช้ `access_token`
กับ `api_host` ธรรมดา ไม่ต้อง OAuth เลย

## OAuth คือส่วนที่ยากจริง และควรยอมรับตั้งแต่ต้น

`rclone authorize <type>` เปิดเบราว์เซอร์ รอ callback ที่ `127.0.0.1` แล้วพิมพ์ token ออกมา
ทำในโปรแกรมได้ แต่:

- ต้องเปิดพอร์ตฟังชั่วคราว และต้องบอกผู้ใช้ว่ากำลังทำอะไร
- **บนเครื่องที่ไม่มีเบราว์เซอร์ (daemon ใน Docker) ทำไม่ได้เลย** ต้อง authorize
  จากเครื่องอื่นแล้วเอา token มาใส่ ซึ่ง rclone รองรับอยู่แล้ว
- ทางลงที่สมเหตุผลคือ **R5 ให้ทางเลือกทั้งสอง** ไม่ใช่บังคับให้เปิดเบราว์เซอร์

## เรื่องที่ต้องระวัง

- **ห้ามแสดงความลับโดยไม่ตั้งใจ** ใช้ `config redacted` สำหรับการแสดงผล
  ส่วน `config show` ใช้เฉพาะตอนที่ผู้ใช้ขอเห็นจริงๆ และไม่เข้า log
  (`debug_log.cpp` ปิดบังคำที่ดูเหมือน token อยู่แล้ว แต่ไม่ควรพึ่งอย่างเดียว)
- **config ที่เข้ารหัสไว้** ต้องถามรหัสก่อนทำอะไรได้ ซึ่ง `RemoteRegistry` แยก
  กรณีนี้ออกมาเป็นสัญญาณของตัวเองแล้ว
- **แก้ config ขณะมีงานวิ่งอยู่** — งานที่รันอยู่ถือค่าเดิมไว้แล้ว แต่การลบ remote
  ที่กำลังถูกใช้ควรเตือน
- **ไม่ตัดทางเดิม** ปุ่มเปิด `rclone config` ในเทอร์มินัลควรอยู่ต่อไป
  คนที่ถนัดแบบนั้นและกรณีที่ UI ยังทำไม่ได้ ต้องยังทำได้

## ทำแล้ว (2026-10-19) — R1 · R2 ฝั่ง core · API · หน้าเว็บ

ผู้ใช้: *"เริ่มดูเรื่องการตั้งค่ารีโหมดของหน้าเว็บ"*

- **`src/rclone_config.*`** — `ParseProviders` อ่าน `rclone config providers` (69 backend บนเครื่องนี้ teldrive 13 ตัวเลือก ·
  ราว 940 KB จึงอ่านครั้งเดียวต่อ process เก็บไว้ใน `RcloneConfigRegistry`) · `readDump` อ่าน `rclone config dump`
  **ใหม่ทุกครั้ง** (ไฟล์เปลี่ยนได้จากข้างนอก) และ**ไม่เคย log ผลของมัน**
- **`DescribeSettings`** — ค่าของรีโหมดเรียงตามลำดับตัวเลือกของ backend พร้อม help (บรรทัดแรก) · ชนิด · ค่าเริ่มต้น · advanced
  **ค่าลับถูกเอาออกก่อนออกจาก core**: ตัวเลือกที่ rclone บอกว่า `IsPassword` หรือ `Sensitive` และ key ที่ชื่อดูเป็นความลับ
  (pass · secret · token · key · cookie · credential · auth · private) — บอกแค่ว่า "ตั้งไว้แล้ว"
  key ที่ backend ไม่ได้อธิบายถูกตัดสินจากชื่ออย่างเดียว และแสดงท้ายรายการ
- **ทำตามคำว่า Sensitive ของ rclone แม้ดูระวังเกิน** — ซ่อน `client_id` · `drive_id` · `team_drive` · `host` · `user` · `api_host` ด้วย
  เพราะคือสิ่งที่ `rclone config redacted` ซ่อน ถ้ามีกฎของเราเองซ้อนอีกชั้นจะกลายเป็นสองกฎ
- **API**: `GET /providers` (รายชื่อ backend) · `GET /providers/{name}` (ตัวเลือกทั้งหมด — สิ่งที่ฟอร์ม R4 จะสร้างจาก) ·
  `GET /remotes/{name}/config` (ค่าแบบปิดความลับ · **ต้องเป็น admin** แม้ไม่มีความลับ เพราะเป็นเรื่องของเจ้าของ)
- **หน้าเว็บ**: ปุ่ม **Settings** ในแถบเครื่องมือของรีโหมด → ตารางค่า · ค่าลับขึ้นว่า "set — not shown" · ป้าย advanced
- **ตรวจกับของจริง**: ทั้ง 7 รีโหมด (onedrive · drive · sftp · teldrive ×4) — เทียบกับ config dump จริงแล้ว**ไม่มีค่าลับหลุดเลย**
- ⚠ **หน้าต่างยังดูค่าเหล่านี้ไม่ได้** (มีแต่ปุ่มเปิด `rclone config` ในเทอร์มินัล) — ตามกติกาข้อ 1 ต้องเพิ่มในหน้าต่างด้วย

## ทำแล้ว (2026-10-19) — R3 ลบ · เปลี่ยนชื่อ

- **เปลี่ยนชื่อ** — rclone ไม่มีคำสั่ง rename จึง `config create <ใหม่> <type> k=v… --non-interactive --no-obscure`
  ด้วยค่าทั้งหมดจาก dump (รหัสผ่านที่ obscure ไว้แล้วส่งตามเดิม ไม่ obscure ซ้ำ) แล้ว `config delete <เก่า>`
  **ลองกับสำเนา rclone.conf จริงก่อน**: drive (มี OAuth token) · sftp · teldrive ได้สำเนาที่เหมือนเดิมทุกค่า
- **task ที่ชี้ไปยังรีโหมดนั้นเปลี่ยนชื่อตาม** (source/dest ที่ขึ้นต้นด้วย `เก่า:`) และคำตอบบอกว่า task ไหนเปลี่ยน
- **ลบ** — `config delete` · ไฟล์บนรีโหมดไม่ถูกแตะ · ถ้ามี task ชี้อยู่ ปฏิเสธพร้อมรายชื่อ task เว้นแต่ `force=1` (task คงไว้ตามเดิม)
- **ทั้งสองอย่างปฏิเสธขณะมีงานใช้รีโหมดนั้นอยู่** · ชื่อใหม่ถูกตรวจตามกฎของ rclone และห้ามซ้ำ
- **API**: `PUT /remotes/{name}/config {"name": …}` · `DELETE /remotes/{name}` — ต้องเป็น admin
  (เลือก DELETE ที่ตัวรีโหมด ไม่ใช่ `/delete` ซึ่งเป็นการลบไฟล์) · ส่งช่องอื่นนอกจาก name → 400 "ยังเปลี่ยนไม่ได้"
- **หน้าเว็บ**: ในกล่อง Settings มีปุ่ม Rename this remote… · Delete this remote… (ถ้ามี task ใช้อยู่ ถามอีกครั้งพร้อมรายชื่อ)
- **ตรวจกับโปรแกรมจริง**: สำรอง rclone.conf ไว้ · สร้างรีโหมดทดสอบชนิด local · เปลี่ยนชื่อผ่าน API · ลบผ่าน API ·
  เทียบ config ทั้งไฟล์ก่อน/หลัง — **รีโหมดของผู้ใช้เหมือนเดิมทุกค่า** ไม่มีรีโหมดทดสอบค้าง
- ⚠ ระหว่างเปลี่ยนชื่อ ค่าลับอยู่ในอาร์กิวเมนต์ของ `rclone config create` ชั่วครู่ (มองเห็นได้จากรายการ process ของเครื่องเดียวกัน)
  — rclone ไม่มีทางส่งค่าทาง stdin ให้คำสั่งนี้ ทางที่ปิดได้คือใช้ rc API (`config/create`) ภายหลัง
- ⚠ หน้าต่างยังไม่มีปุ่มเปลี่ยนชื่อ/ลบรีโหมด (ต้องผ่าน `rclone config`) — ต้องเพิ่มตามกติกาข้อ 1

**ค่าอ่อนไหวหลุดหนึ่งค่า — เจอจากภาพหน้าจอของผู้ใช้ (2026-10-19) และแก้แล้ว**
คำขอแรกหลังเปิดโปรแกรมตอบก่อนที่ข้อมูล backend จะโหลดเสร็จ ช่วงนั้นมีแค่การเดาจากชื่อ
`api_host` ของ teldrive (ซึ่ง rclone ถือว่า sensitive) จึงแสดงค่าออกไปบนหน้าเว็บ test ไม่เจอเพราะทุก test โหลดข้อมูล backend ก่อนถาม
แก้สองชั้น: (1) **API รอให้ rclone อธิบาย backend ก่อนตอบ** (สูงสุด 15 วินาที) · (2) **ถ้าไม่มีคำอธิบายของ backend เลย
ซ่อนทุกค่า** — ชื่ออย่างเดียวไม่พอจะบอกว่าอะไรเป็นความลับ · test ใหม่ถามเป็นอย่างแรกหลังเริ่ม และโปรแกรมจริงตอบใน 0.8 วินาทีโดยซ่อน api_host

## ทำแล้ว (2026-10-19) — R4 สร้าง · แก้

ลองกับไฟล์ config ทิ้งได้ก่อน: **rclone รับ key อะไรก็ได้แล้วเขียนลงไฟล์** (`nonsense=1` ถูกบันทึก) และ**ไม่บังคับช่อง required**
— จึงต้องตรวจเอง · drive แบบ `--non-interactive` ถูกบันทึกทั้งที่ยังไม่มี token แล้วถามต่อว่าจะเปิด browser ไหม ·
`config update` ของ drive ไม่ทำให้ token หาย (เทียบ hash ก่อน/หลังบนสำเนา config จริง) แต่ตอบเป็นคำถาม `config_refresh_token`

- **`CreateRemote`** — `config create <ชื่อ> <type> k=v… --non-interactive --obscure` (รหัสผ่านส่งตามที่พิมพ์ rclone obscure ให้)
- **`UpdateRemote`** — `config update <ชื่อ> k=v… --non-interactive --obscure` เฉพาะค่าที่ส่งมา · ค่าลับที่ไม่ได้ส่ง = คงเดิม
- **`WhyNotSettings`** — เฉพาะ option ที่ backend มี (กันการยัด key แปลกหรือ `--config` ลงไฟล์) · ห้ามขึ้นบรรทัดใหม่ ·
  bool ต้อง true/false · ตัวเลือกแบบ exclusive ต้องอยู่ในรายการ · สร้างใหม่ต้องมีทุกช่อง required
- **ชนิดที่ sign in ผ่าน browser (มี option `token`) สร้างไม่ได้จนกว่า R5** — 409 `signs_in_with_browser` · แต่**แก้ได้**
- คำถามที่ rclone จะถามต่อ (เช่น refresh token หลังแก้ drive) ถูกบอกในคำตอบเป็น `asks` ไม่ถือเป็นความล้มเหลว
- **API**: `POST /remotes {name, type, settings}` → 201 · `PUT /remotes/{name}/config {settings?, name?}` (settings ก่อน แล้วเปลี่ยนชื่อ) · admin
  ทั้งคู่รอให้ rclone อธิบาย backend ก่อน (`afterBackendsAreKnown`) เหมือนการอ่าน
- **หน้าเว็บ**: การ์ด **+ New remote** ท้ายรายการรีโหมด → เลือกชนิด (ค้นหาได้) · ตั้งชื่อ · ฟอร์มสร้างจาก `/providers/{type}`:
  bool = checkbox · ตัวเลือก exclusive = รายการ · มีตัวอย่าง = ช่องที่มีคำแนะนำ · รหัสผ่าน/sensitive = ช่องรหัส (เว้นว่าง = คงเดิม) ·
  advanced ซ่อนหลังลิงก์ (เปิดเองถ้ารีโหมดตั้งค่า advanced ไว้) · กล่อง Settings มีปุ่ม **Edit settings…** · ส่งเฉพาะค่าที่เปลี่ยน
- **ตรวจกับโปรแกรมจริง** (สำรอง config ไว้ก่อน): sftp ที่ขาด host → 400 · drive → 409 · sftp ครบ → 201 รหัสผ่านถูก obscure ·
  แก้ port → รหัสผ่านคงเดิม · ลบ → **รีโหมดของผู้ใช้เหมือนเดิมทุกค่า**
- ⚠ ยังไม่ได้ดูฟอร์มบนหน้าเว็บด้วยตา · ค่าลับอยู่ในบรรทัดคำสั่งของ rclone ชั่วครู่ (เหมือน R3)

**ขั้นต่อไป**: R5 OAuth — ทางที่ใช้ได้ทั้งบนเครื่องและใน Docker คือให้ผู้ใช้รัน `rclone authorize <type>` บนเครื่องที่มี browser
แล้ววาง token ที่ได้ลงในหน้าเว็บ (rclone รองรับอยู่แล้ว) · ทางที่สะดวกกว่า (เปิด browser ให้เอง) ใช้ได้เฉพาะเมื่อ browser อยู่เครื่องเดียวกับโปรแกรม

**ตัดสินแล้วระหว่างทาง**: การเขียนจะเรียก `rclone config create/update/delete` เสมอ ไม่เขียนไฟล์เอง
(rclone รู้เรื่อง obscure และรหัสผ่านของ config ที่เข้ารหัส)

## ที่ยังไม่ตัดสิน

- เขียน config เองโดยตรง หรือเรียก `rclone config create` เสมอ
  (เรียก rclone ปลอดภัยกว่า เพราะมันรู้เรื่อง obscure/รหัสผ่านของตัวเอง)
- ฟอร์มที่สร้างจาก JSON จะจัดกลุ่ม `Advanced` ยังไง — ซ่อนไว้หลังปุ่ม หรือแยกแท็บ
- จะรองรับ `config reconnect` สำหรับ token ที่หมดอายุเมื่อไหร่
