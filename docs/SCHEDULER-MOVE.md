# แผนย้ายตารางเวลาเข้า `SchedulerStore` — ผังของสิ่งที่ต้องแตะ

> เขียน 2026-08-25 · ประกอบกับ [`API.md` §12 S4](API.md) · ทำต่อจาก [`QUEUE-MOVE.md`](QUEUE-MOVE.md)
> ใช้ครั้งเดียวแล้วทิ้งได้เมื่อย้ายเสร็จ

## ทำไมต้องมีเอกสารนี้

เพราะการย้ายคิวสอนไปแล้วว่า **ประเมินด้วยสายตาจะพลาดสามเท่า** ครั้งนั้นเดาว่า 20 จุด
ของจริง 118 จุด ครั้งนี้จึงนับก่อนลงมือ

**149 จุดอ้างอิง** ใน `main_window.cpp` (นับจาก `SchedulerWidget`, `mSchedulersCount`,
`mRunningSchedulersCount`, `ui.schedulers`, `saveSchedulerFile`, ปุ่มและป้ายทั้งสอง)

## ตารางเวลาตัวจริงตอนนี้อยู่ที่ไหน

เหมือนคิวเป๊ะ — **มันคือ layout ไม่ใช่ข้อมูล**

```cpp
int schedulersCount = ui.schedulers->count();
for (int j = schedulersCount - 2; j >= 0; j = j - 2) {
  QWidget *w = ui.schedulers->itemAt(j)->widget();
  if (auto scheduler = qobject_cast<SchedulerWidget *>(w)) { ... }
}
```

บรรทัดนี้ปรากฏ **16 ครั้ง** `- 2` และ `j - 2` เพราะใน layout มี widget สลับกับเส้นคั่น
`QFrame` — **ลำดับของตารางเวลาคือลำดับของ widget ในกล่อง** และ "มีตารางเวลากี่อัน"
ตอบได้ด้วยการหารสองเท่านั้น

| สิ่งที่เป็นอยู่ | ความหมาย | จะกลายเป็น |
|---|---|---|
| ลำดับ widget ใน `ui.schedulers` | รายการตารางเวลา | `SchedulerStore::schedules()` |
| `mSchedulersCount` | มีกี่ตาราง | `count()` |
| `mRunningSchedulersCount` | กี่ตารางที่งานกำลังวิ่ง | นับจาก `runningRequestId` |
| `Settings/schedulerStatus` | เปิด/ปิดทั้งระบบ | `isRunning()` ของ store |
| `QTimer` ใน **ทุก** widget | ถึงเวลาหรือยัง | `due()` ครั้งเดียวใน store |
| 23 ฟิลด์ใน widget | ตัวตารางเวลาเอง | `Schedule` |

## บล็อกที่ต้องย้าย

| # | อยู่ใน | ตัดสินใจอะไร | จะกลายเป็น | สถานะ |
|---|---|---|---|---|
| 1 | 19 จุดทั่วไฟล์ | เขียนข้อความแท็บ + ปุ่ม + ป้าย | `refreshSchedulerView()` | ✅ **ทำแล้ว** |
| 2 | 16 จุดเดิน layout | "ตารางเวลามีอะไรบ้าง" | `schedulerWidgets()` → `SchedulerStore::schedules()` | ✅ **ทำแล้ว (ตัวกลาง)** |
| 3 | 6 จุด "notify schedulers" | บอกทุกตารางว่างานเปลี่ยนสถานะ | `notifySchedulers()` → store ฟัง `JobRegistry` เอง | ✅ **ทำแล้ว (ตัวกลาง)** |
| 4 | `actionStartScheduler` / `actionStopScheduler` + 4 จุดอ่าน setting | เปิด/ปิดทั้งระบบ | `SchedulerStore::start()` / `pause()` / `isRunning()` | ✅ **ทำแล้ว (ของจริง)** |
| 5 | `actionAddToScheduler` | สร้างตารางใหม่ | `add(Schedule)` | ⬜ |
| 6 | `restoreSchedulersFromFile()` / `saveSchedulerFile()` | อ่าน/เขียนตอนเปิด-ปิด | `load()` / `save()` | ⬜ |
| 7 | `SchedulerWidget::checkSchedule()` × N | ถึงเวลาหรือยัง | `due()` ตัวเดียว | ⬜ |
| 8 | `SchedulerWidget::runTask` handler | ส่งงานเข้าคิว/รันทันที | `enqueue()` (มีอยู่แล้ว) | ⬜ |
| 9 | 23 ฟิลด์ใน widget | ตัวตารางเวลาเอง | `Schedule` | ⬜ |

**บล็อก 2 กับ 3 คือ "ตัวกลาง"** ตามวิธีที่ใช้ตอนย้ายคิว — ยังเดิน layout อยู่ แต่เดินที่เดียว
พอ `SchedulerStore` พร้อม เปลี่ยนแค่ข้างในสองฟังก์ชันนี้ ไม่ต้องแตะ 149 จุดอีก

**บล็อก 4 ย้ายจริงแล้ว** สวิตช์เปิด/ปิดทั้งระบบเคยเป็น `Settings/schedulerStatus`
ที่หน้าต่างอ่านเอง 6 ที่ — ตอนนี้เป็น `SchedulerStore::isRunning()` และ
`due()` เป็นคนบังคับกฎเอง ไม่ใช่หน้าต่าง

ระหว่างย้ายเจอกับดักหนึ่ง: ถ้า `due()` แค่ `return {}` ตอนปิดอยู่ **นาทีที่ผ่านไปตอนปิด
จะถูกรันย้อนหลังทันทีที่เปิดกลับมา** เพราะไม่ได้จดว่าเห็นนาทีนั้นแล้ว
ของเดิมไม่เป็นแบบนั้น (widget เลื่อน `mNextRun` ไปเรื่อยๆ แม้ตอนหยุด)
จึงต้องจด `mLastFired` ก่อนแล้วค่อย `continue` — มี test คุมไว้แล้ว

## ขั้น 0 — วางเครื่องวัดก่อน (ทำแล้ว)

การย้ายคิวพิสูจน์ว่า **หลังบ้านถูกไม่ได้แปลว่าหน้าจอถูก** ตราบใดที่หน้าต่างยังมีทางเดินที่สอง
คราวนั้น test จับได้เพราะคิวเป็น logic ล้วน แต่ `SchedulerWidget` มี ui refs 334 จุด
test แบบ headless เข้าไม่ถึง

จึงใช้ **debug log เป็นเครื่องวัดแทน** — commit `62adaed` ใส่หมวด `rb.sched`
ที่ทำให้ทุกการตัดสินใจของตารางเวลาพูดออกมา ย้ายเสร็จแล้วเทียบ log ก่อน-หลังได้ว่า
`check` / `fired` / `held` ยังออกในจังหวะเดิม ดู [`VERIFY.md` V-22](VERIFY.md)

## บล็อก 1 — ที่เดียวที่เขียนแท็บ Scheduler (ทำแล้ว)

ข้อความแท็บถูกเขียน **19 ที่** และ **สะกดไม่เหมือนกัน**:

- `Scheduler (2)>>(1)` — เมื่อ scheduler เปิดอยู่ (15 ที่)
- `Scheduler (2)` — เมื่อ scheduler ปิดอยู่ (3 ที่)
- `Scheduler (0)>>(0)` — ฝังตายตอนสร้างหน้าต่าง (1 ที่)

**กฎไม่เคยกำกวม แต่ไม่มีที่อยู่** จุดไหนได้แบบไหนขึ้นกับว่าคนแก้ก๊อปมาจากจุดไหน

ที่เจอระหว่างทาง — สองอย่างนี้แก้ให้ตรงกันแล้วโดยไม่ได้ตั้งใจจะแก้:

1. `restoreSchedulersFromFile()` เขียนแบบยาวเสมอ แม้ scheduler ปิดอยู่
   รอดมาได้เพราะโค้ดที่ตามมาอีกไม่กี่บรรทัดเขียนทับให้ถูก
2. ตอนสร้างหน้าต่างฝัง `(0)>>(0)` ไว้ **แท็บจึงบอกว่า scheduler เปิดอยู่
   ก่อนที่จะมีใครอ่านค่า setting**

หลังจากนี้ `if/else` สองแห่งหายไปทั้งก้อน เพราะสองสาขาต่างกันแค่การสะกดแท็บ
ซึ่งไม่ใช่เรื่องที่มันตั้งใจจะตัดสินตั้งแต่แรก

## บทเรียนจากการย้ายคิวที่ใช้ซ้ำได้

- **ทำตัวกลางก่อน แล้วตัดทีละตัว** — อย่าเปลี่ยนทั้งก้อน
- **ระวังสองคนขับพร้อมกัน** — `setDrivesItself` มีไว้เพราะเรื่องนี้ ตารางเวลาก็ต้องมีสวิตช์แบบเดียวกัน
- **ฆ่าโปรแกรมก่อนบิ้วเสมอ** และเช็ค `EXIT` กับ `LastWriteTime` ของ exe ก่อนให้คนทดสอบ
- **สคริปต์แทนที่ข้อความต้องมี `assert`** ไม่งั้นการแทนที่ที่ไม่สำเร็จจะกลายเป็นบั๊กปลอมให้ไล่

## บทเรียนใหม่ 2026-08-25 — ห้ามแก้ซอร์สด้วย PowerShell

ระหว่างทำบล็อก 2 ใช้คำสั่งนี้เพื่อลบ `const` ออกจาก loop:

```powershell
(Get-Content src\main_window.cpp) -replace '...' | Set-Content src\main_window.cpp -NoNewline
```

`Get-Content` คืน **array ของบรรทัด** และ `Set-Content -NoNewline` เขียนต่อกัน**โดยไม่ใส่ตัวขึ้นบรรทัด**
ผลคือไฟล์ 3,909 บรรทัดกลายเป็นบรรทัดเดียว และ **กู้ไม่ได้** เพราะ `//` กลืนทุกอย่างที่เหลือ

ต้อง `git checkout` แล้วทำใหม่ทั้งหมด เสียงานไปราวครึ่งชั่วโมง

**กฎจากนี้ไป:** แก้ซอร์สด้วย `Edit` หรือสคริปต์ Python ที่ `assert` เท่านั้น
PowerShell ใช้ได้แค่รันคำสั่ง ไม่ใช่เขียนไฟล์
