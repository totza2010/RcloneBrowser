> เขียน 2026-08-25 · ทำต่อจาก [`QUEUE-MOVE.md`](QUEUE-MOVE.md) และ [`SCHEDULER-MOVE.md`](SCHEDULER-MOVE.md)

## "แยกขาด" แปลว่าอะไรกันแน่

ไม่ใช่ "ไม่มี violation" — ตอนนี้ก็ไม่มีอยู่แล้ว `rbcore` ลิงก์แค่ Core, Network, Sql
ไม่มี Widgets **linker เป็นคนบังคับ ไม่ใช่คนรีวิว** และ `scripts/check_layers.py` ผ่านมาตลอด

เกณฑ์ที่ใช้ในเอกสารนี้แคบกว่านั้น และวัดได้:

> **ทุกการตัดสินใจต้องมีบ้านอยู่นอกหน้าต่าง**
> หน้าต่างเหลือแค่สองหน้าที่: วาดสิ่งที่ core บอก และส่งสิ่งที่ผู้ใช้กดเข้าไปให้ core
>
> ข้อพิสูจน์คือ **ถามคำถามนั้นโดยไม่มีหน้าต่างแล้วต้องได้คำตอบ**

## กฎที่ใช้ตลอด — มาจากบทเรียนสองรอบก่อน

1. **นับก่อนลงมือ** ตอนย้ายคิวเดา 20 ของจริง 118 ตอนย้าย scheduler นับได้ 149
2. **ทำตัวกลางก่อน แล้วตัดทีละตัว** อย่าเปลี่ยนทั้งก้อน
3. **ระวังสองคนขับพร้อมกัน** — `setDrivesItself` มีไว้เพราะเรื่องนี้
4. **แก้ซอร์สด้วย `Edit` หรือ Python ที่ `assert`** ห้าม PowerShell เขียนไฟล์
5. **ฆ่าโปรแกรมก่อนบิ้ว** เช็ค `EXIT` กับ `LastWriteTime` ก่อนให้คนทดสอบ
6. **วางเครื่องวัดก่อนผ่าตัด** — ใส่ log ก่อนย้าย จะได้เทียบก่อน-หลังได้

## ข้อ 6 คือหัวใจของรอบนี้

ทุกบล็อกต้องเพิ่มบรรทัด log ที่**พิสูจน์ว่าใครเป็นคนตัดสินใจ** เพราะเกณฑ์รับงานของรอบนี้
ไม่ใช่ "คอมไพล์ผ่าน" แต่คือ **อ่าน log แล้วเห็นว่า core เป็นคนตอบ ไม่ใช่หน้าต่าง**

หมวดใหม่ที่จะเพิ่ม: `rb.script` · `rb.remote` · `rb.task`

ตารางทดสอบ [`VERIFY.md` V-24](VERIFY.md) จึงมีคอลัมน์ **"บรรทัดที่ต้องเห็นใน log"**
ทุกแถว — ถ้าไม่มีบรรทัดนั้น แปลว่ายังไม่ได้ย้าย ต่อให้โปรแกรมทำงานถูกก็ตาม

## บล็อก 1 เสร็จแล้ว — และวิธีทำงานนี้จับของตัวเองได้ทันที

`ScriptRunner` (L1) ฟัง `JobQueue::emptied` และ `JobRegistry` เอง ตัด 4 จุดใน
`main_window` ทิ้ง หมวด log ใหม่ `rb.script` → `logs/scripts/scripts.txt`

**ผ่าน build ผ่าน test 18 ชุด แต่ข้อ 1.7 ไม่ผ่าน** — งานรันจบ exit 0 แต่ไม่มีบรรทัด
`rb.script` เลยสักบรรทัด สองสาเหตุซ้อนกัน:

1. `ScriptRunner::install()` ถูกเรียกจาก `MainWindow` เท่านั้น
2. **`TaskRunner` ไม่ได้เดินผ่าน `JobRegistry`** — มันรัน rclone เองด้วย `QProcess`
   ของตัวเอง สัญญาณ `jobStarted`/`jobFinished` จึงไม่เคยเกิดในโหมดไม่มีหน้าต่าง

นี่คืออาการ **"แยกครึ่งเดียว"** ที่เอกสารนี้เตือนไว้ในหัวข้อข้างบนเอง — ย้ายความสามารถ
เข้า core แล้ว แต่**การต่อสาย**ยังผูกกับหน้าต่าง

แก้โดยให้ `TaskRunner` เรียก `ScriptRunner::run(..., waitForIt=true)` ที่จุดเริ่มและจุดจบ
`waitForIt` จำเป็นเพราะ process กำลังจะจบ — script ที่ไม่รอ คือ script ที่ถูกฆ่าทันที

> **ข้อค้นพบที่ยังไม่ได้แก้:** `TaskRunner` ไม่เดินผ่าน `JobRegistry` แปลว่างานที่สั่งจาก
> command line ไม่มี job card ไม่มี stats ไม่มีทางหยุดจากที่อื่น และเขียนประวัติเอง
> คนละทางกับงานในหน้าต่าง **สมควรเป็นบล็อกของตัวเอง** ก่อนทำ S11 เพราะ API
> จะต้องสั่งงานแล้วเห็นงานนั้นเหมือนกับที่หน้าต่างเห็น

## บล็อก 2 เสร็จแล้ว

`RemoteRegistry::refresh()` **มีอยู่แล้วตั้งแต่ S5** ครบทั้งการรัน การอ่าน และการแยก
"ต้องใส่รหัสผ่าน" ออกจาก "ล้มเหลว" — **แต่ไม่มีใครเรียกมัน** หน้าต่างยังรัน process
ของตัวเองอยู่ นี่คืออาการ "แยกครึ่งเดียว" อีกแบบหนึ่ง: **ของที่ย้ายไปแล้วแต่ไม่ได้ถูกใช้**
ซึ่งมองจาก `check_layers.py` ไม่เห็นเลย เพราะไม่มีอะไรผิดกฎ

ตอนนี้ `rcloneListRemotes()` เหลือบรรทัดเดียว และ `drawRemotes()` วาดจากสิ่งที่ registry ถือ
ส่วน "ต้องใส่รหัสผ่าน" / "rclone เก่าเกินไป" เป็น signal ที่หน้าต่างรับไปตอบ
แทนที่จะไปอ่าน stderr ของ rclone เอง

`ParseRcloneVersion()` แยกออกมาเป็น `rclone_version.h` พร้อม `atLeast()` ที่เทียบทีละช่อง
(ของเดิมใช้ `compareVersion()` บน `std::string`) — เป็นฐานของ
[`RCLONE-MANAGER.md`](RCLONE-MANAGER.md) ด้วย เพราะการจัดการหลาย binary
เริ่มจากการตอบให้ได้ว่า "ตัวนี้เวอร์ชันอะไร"

**GUI-free 64/107 → 66/109**
