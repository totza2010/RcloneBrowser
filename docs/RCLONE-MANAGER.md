# แผน: ให้โปรแกรมจัดการ rclone เองได้

> เขียน 2026-08-26 · ยังไม่ได้ลงมือ · ต่อจาก [`LAYER-SPLIT.md`](LAYER-SPLIT.md) บล็อก 2

## ปัญหาที่มีอยู่จริงบนเครื่องนี้

มี rclone **สองตัว**ติดตั้งอยู่ — ตัวทางการ กับ tgdrive — และโปรแกรมชี้ไปที่ตัวหนึ่ง
ผ่านช่อง path ใน Preferences เท่านั้น

สิ่งที่ตามมา:

- **ไม่มีที่ไหนบอกว่ากำลังใช้ตัวไหน** นอกจากไปอ่าน path เอา — log เพิ่งเริ่มบอกวันนี้
- สลับไปมาต้องพิมพ์ path ใหม่ทุกครั้ง จำเองว่าอันไหนอยู่ที่ไหน
- อัปเดตต้องออกไปทำนอกโปรแกรม แล้วกลับมาเช็คเองว่าได้เวอร์ชันอะไร
- **backend ที่มีไม่เท่ากัน** — teldrive มีเฉพาะใน fork ถ้าชี้ผิดตัว remote จะหายไปเฉยๆ
  โดยไม่มีอะไรอธิบาย

ข้อสุดท้ายสำคัญที่สุด เพราะอาการของมันคือ "remote หาย" ซึ่งดูเหมือนข้อมูลเสีย
ไม่ใช่เหมือนตั้งค่าผิด

## เป้าหมาย

ให้โปรแกรมรู้จัก rclone **หลายตัว** สลับได้ ติดตั้งเพิ่มได้ อัปเดตได้ โดยไม่ต้องออกไปข้างนอก

## รูปร่างที่คิดไว้

```
RcloneInstall {
  QString id;          // "official" · "tgdrive"
  QString label;       // ชื่อที่คนอ่าน
  QString path;        // ไฟล์จริงบนดิสก์
  QString repo;        // rclone/rclone · tgdrive/rclone
  RcloneVersion version;
  bool managed;        // โปรแกรมโหลดมาเอง หรือคนชี้ให้
}
```

`RcloneRegistry` (L1) ถือรายการนี้ · ตัวที่ใช้อยู่คืออันไหน · `GetRclone()` ถามตัวนี้แทน
การอ่าน setting ตรงๆ

## แบ่งเป็นขั้น — ขั้นแรกใช้ได้เองโดยไม่ต้องรอขั้นหลัง

| ขั้น | ทำอะไร | ได้อะไร |
|---|---|---|
| **M1** | รู้จักหลายตัว สลับได้จากเมนู | เลิกพิมพ์ path · เห็นว่าใช้ตัวไหนอยู่ |
| **M2** | ตรวจเวอร์ชันของทุกตัวที่รู้จัก แสดงคู่กัน | รู้ว่าตัวไหนเก่า |
| **M3** | เช็คว่ามีรุ่นใหม่ไหมจาก GitHub releases | รู้ว่าควรอัปเดต |
| **M4** | ดาวน์โหลดและติดตั้งให้ | อัปเดตในโปรแกรม |
| **M5** | รองรับหลาย repo (fork ใดก็ได้) | ลง tgdrive จากโปรแกรมได้ |

**M1 กับ M2 ไม่ต้องต่อเน็ตเลย** และแก้ปัญหาที่เจ็บที่สุด (ไม่รู้ว่าใช้ตัวไหน) ไปแล้วครึ่งหนึ่ง
จึงควรทำก่อน ไม่ต้องรอ M3–M5 ที่ยากกว่ามาก

## สิ่งที่มีอยู่แล้ววันนี้ และใช้ต่อได้

- `RcloneVersion` + `ParseRcloneVersion()` — อ่านเวอร์ชันได้ เทียบเวอร์ชันได้
  รองรับ `-DEV` และ `-beta` ซึ่งเป็นหน้าตาของ build จาก source เช่น fork
- `RcloneFlagRegistry` — รู้อยู่แล้วว่า binary ที่ชี้อยู่รับ flag อะไรบ้าง และ
  `invalidate()` ตอนเปลี่ยน path ซึ่งเป็นครึ่งหนึ่งของงาน "สลับตัว"
- `RcloneCapabilities` — รู้ว่า backend ไหนทำอะไรได้
- `rb.remote` ใน log — บอกแล้วว่าใช้ binary ตัวไหนตอนถาม

**M1 จึงเป็นการรวบของที่มีอยู่ ไม่ใช่เขียนใหม่**

## เรื่องที่ต้องคิดให้ดีก่อนถึง M4

- **ดาวน์โหลดไฟล์ปฏิบัติการมารันคือเรื่องความปลอดภัย** ต้องตรวจ checksum
  ที่ repo ให้มา และต้องบอกผู้ใช้ว่ากำลังโหลดจากที่ไหน ไม่ใช่ทำเงียบๆ
- **fork ไม่รับประกันว่ามี release แบบเดียวกัน** สมมติฐานว่า "GitHub releases มี
  ไฟล์ชื่อแบบนี้เสมอ" จะพังกับ fork ที่ build เอง
- **อย่าทับตัวที่กำลังรันอยู่** งานที่วิ่งอยู่ถือ handle ไฟล์นั้นค้างไว้ (บน Windows
  เขียนทับไม่ได้เลย) ต้องลงคนละที่แล้วค่อยสลับ
- **ยังต้องเลือกเองได้เสมอ** คนที่ลง rclone ผ่าน package manager ต้องชี้ path
  เองได้เหมือนเดิม ไม่ใช่ถูกบังคับให้ใช้ตัวที่โปรแกรมโหลด

## ที่ยังไม่ตัดสิน

- ตัวที่โปรแกรมโหลดมาเอง เก็บไว้ที่ไหน — ข้าง config หรือข้างตัวโปรแกรม
  (โหมด portable ตอบไม่เหมือนกัน)
- เก็บของเก่าไว้กี่รุ่นเผื่อถอย
- สลับตัวขณะมีงานวิ่งอยู่ ควรห้าม หรือให้รอ
