> เขียน 2026-10-12 · สถานะ: **ขั้น 1–3 เสร็จ** · อิมเมจ build และรันได้ครบสามโหมดบนเครื่องผู้พัฒนา
> **ยังไม่ได้ push อิมเมจ และ workflow ยังไม่ได้รันจริง** · วิธีใช้อยู่ที่ [`docker/README.md`](../docker/README.md)

## เป้าหมาย

| `RB_MODE` | สิ่งที่รัน | เข้าทางไหน |
|---|---|---|
| `web` | `--daemon` อย่างเดียว ไม่เปิดชั้นส่งหน้าจอ | หน้าเว็บของเรา |
| `both` | หน้าต่าง Qt บนตัวส่งหน้าจอ ซึ่งมีหน้าเว็บของเราไปด้วยในตัว | ทั้งสองทาง |
| `desktop` | หน้าต่าง Qt บนตัวส่งหน้าจอ โดย `Settings/apiEnabled=false` | ตัวส่งหน้าจออย่างเดียว |

ฝั่งโปรแกรมรองรับครบแล้ว: โหมด `both` คือการเปิดโปรแกรมตามปกติ และ lock ร่วมกัน
กันไม่ให้ daemon กับหน้าต่างรันซ้อนในคอนเทนเนอร์เดียว ดู [`WEB-UI.md`](WEB-UI.md)

เพราะอิมเมจเดียวต้องรองรับโหมดที่มีหน้าต่าง **ตัวส่งหน้าจอจึงต้องอยู่ในอิมเมจเสมอ**
คำถามเหลือแค่ว่าใช้ตัวไหน

## ตัวส่งหน้าจอ: Selkies แทน noVNC

ฐานที่จะใช้คือ `ghcr.io/linuxserver/baseimage-selkies:alpine324`
ตรวจจากอิมเมจจริงเมื่อ 2026-10-12:

| เรื่อง | ที่พบ |
|---|---|
| Alpine | 3.24.2 — ตรงกับที่ Dockerfile เรา build อยู่ จึงไม่ต้องเปลี่ยน distro |
| ขนาด | **583 MB** ก่อนใส่อะไรของเรา |
| พอร์ต | 3000 (HTTP) · 3001 (HTTPS, self-signed) |
| โหมดจอ | **X11 เป็นค่าเริ่มต้น** (`DISPLAY=:1`, Xvfb + openbox) · Wayland เปิดด้วย `PIXELFLUX_WAYLAND=true` (labwc) |
| Xwayland | มี — โปรแกรม X11 อย่าง `xterm` จึงยังใช้ได้ในโหมด Wayland |
| เปิดแอป | เขียนคำสั่งลง `/defaults/autostart` (X11) และ `/defaults/autostart_wayland` |
| init | s6-overlay · บริการที่เกี่ยว: `svc-xorg` `svc-de` `svc-selkies` `svc-nginx` `svc-pulseaudio` |
| Qt | ไม่มีมาให้ ต้องลงเอง |

### plugin Wayland ของ Qt

บน Alpine 3.24 (Qt 6.11.1) ตัว client ของ Wayland ย้ายเข้ามาอยู่ใน qtbase แล้ว:

| แพ็กเกจ | ขนาด | ให้อะไร |
|---|---|---|
| `qt6-qtbase-x11` (ที่ลงอยู่แล้ว) | 21 MB | `platforms/libqxcb.so` |
| **`qt6-qtbase-wayland`** | **2.4 MB** | `platforms/libqwayland.so` · `wayland-shell-integration/libxdg-shell.so` · decoration |
| `qt6-qtwayland` | 3.3 MB | ฝั่ง **compositor** — เราไม่ต้องใช้ |

สรุป: **ลงเพิ่มแค่ `qt6-qtbase-wayland` ตัวเดียว** ก็รันได้ทั้งสองโหมดจอ
และเพราะฐานเริ่มที่ X11 อยู่แล้ว **ถึงไม่ลงก็ยังรันได้** ด้วย plugin `xcb` ที่มีอยู่เดิม

ที่ยังไม่ได้ลอง: เปิดหน้าต่างจริงบน labwc ว่าเมนู, กล่องเลือกไฟล์ และ tray ทำงานครบไหม
tray icon เป็นจุดที่น่าสงสัยที่สุด เพราะบน Wayland ต้องพึ่ง StatusNotifier ผ่าน D-Bus

### โหมด `web` ต้องปิดบริการของ Selkies

s6-rc คอมไพล์รายการบริการ**ตอนคอนเทนเนอร์เริ่ม ก่อนสคริปต์ init ใดๆ จะรัน**
จึงปิดบริการจากสคริปต์ `cont-init` ไม่ได้ ทางที่ใช้ได้คือ **entrypoint ของเราเองที่ห่อ `/init`**:
ถ้า `RB_MODE=web` ให้ลบ `svc-xorg` `svc-de` `svc-selkies` `svc-pulseaudio` ออกจาก
`/etc/s6-overlay/s6-rc.d/user/contents.d/` แล้วค่อย `exec /init` — ยังไม่ได้ลอง

### ของที่ต้องยอมรับ

- **อิมเมจใหญ่เท่าโหมดที่หนักที่สุดเสมอ** โหมด `web` ใช้จริงแค่ qtbase กับ SQLite
  แต่ยังแบกฐาน 583 MB ไว้ในดิสก์ ถ้าอยากได้ตัวเล็กต้องแยกเป็นอีก tag จาก Dockerfile เดียวกัน
- **HTTPS ของ Selkies เป็น self-signed** browser จะเตือนจนกว่าจะวาง reverse proxy
- **หน้าเว็บของเราผูกกับ 127.0.0.1 เป็นค่าเริ่มต้น** ในคอนเทนเนอร์ต้องตั้ง `Settings/apiAddress=0.0.0.0`
  ซึ่งเป็นการเปิดออกเครือข่าย จึงควรบังคับให้ตั้งรหัสผ่าน admin ก่อน

## ขั้น 1 — หยุดอย่างสุภาพ ✅

`docker stop` ส่ง SIGTERM รอสิบวินาที แล้วฆ่า เดิมไม่มีอะไรฟังสัญญาณเลย: rclone ถูกตัดกลางไฟล์
ประวัติค้างที่ "running" และคิวไม่รู้ว่าเกิดอะไรกับรายการหัวแถว

ตอนนี้มีสามทางที่ไปจบที่ฟังก์ชันเดียวกัน:

| ทาง | สำหรับ |
|---|---|
| SIGTERM · SIGINT · SIGHUP | `docker stop` · systemd · Ctrl+C บน Linux/macOS |
| Ctrl+C · ปิด console · ปิดเครื่อง | Windows |
| `POST /api/v1/shutdown` | ที่ที่ส่งสัญญาณไม่ได้ · **daemon เท่านั้น** หน้าต่างตอบ 409 |

`AppCore::shutdown()` ทำตามลำดับ:

1. **นาฬิกาไม่เริ่มงานใหม่** ตารางเวลาที่ถูกสั่งรันตอนนี้ถูกปฏิเสธพร้อมเหตุผล
2. **คิวถูก "ถือไว้"** (`JobQueue::setHeld`) — ไม่ใช่ pause
3. **สั่งทุกงานให้หยุด** transfer ถูกจบ · mount ถูก unmount
4. **รอจนหยุดจริง** ไม่เกิน 8 วินาที เพราะประวัติถูกเขียนตอน rclone ออกจริงเท่านั้น

**ทำไมต้อง "ถือ" ไม่ใช่ pause** — pause ถูกจำข้ามการรีสตาร์ต คิวที่ pause เพื่อปิดโปรแกรม
จะกลับมาในสภาพ pause และ daemon ที่รีสตาร์ตมาเจอคิวหยุดอยู่ คือ daemon ที่เลิกทำงานไปเงียบๆ
ส่วนการหยุดงานโดยปล่อยคิวเดินอยู่ จะ**ทิ้งรายการนั้นแล้วเริ่มรายการถัดไป** ซึ่งผิดทั้งสองอย่าง
คิวที่ถูกถือไว้เก็บทุกรายการรวมทั้งตัวที่กำลังรัน ไม่เริ่มอะไร และอ่านกลับมาได้เหมือนเดิมทุกประการ

ตรวจแล้วบน Linux จริง: daemon ใน Alpine 3.24 โดน `docker stop` → ออกใน **0.6 วินาที รหัส 0**
พร้อมบรรทัด `stopping (SIGTERM)... stopped`

**ที่ยังไม่ได้ตรวจ:** หยุดขณะมี transfer จริงกำลังวิ่งในคอนเทนเนอร์ (`test_shutdown` ครอบด้วย
`fake_rclone`) และกรณี mount ที่ unmount ไม่ลงเพราะมีไฟล์เปิดค้าง — กรณีนั้นจะเกิน 8 วินาที
แล้วโดน Docker ฆ่า

## ขั้น 2–3 — สามโหมดบนฐาน Selkies ✅

| ชิ้น | ทำอะไร |
|---|---|
| `/rb-init` | entrypoint ที่ห่อ `/init` — โหมด `web` ลบบริการเดสก์ท็อปออกจากรายการก่อน supervisor อ่าน |
| `svc-rclonebrowser` | บริการ s6 ที่รัน `--daemon` ในโหมด `web` · โหมดอื่นหลับ |
| `/usr/bin/rb-desktop` | ตัวเปิดหน้าต่าง เรียกจาก autostart ของเดสก์ท็อป |
| `RB_API_ENABLED` · `RB_API_ADDRESS` · `RB_API_PORT` | ตัวแปรที่โปรแกรมอ่านเอง **ชนะค่าที่บันทึกไว้** |

**ทำไมโหมดถูกส่งผ่าน environment ไม่ใช่ไฟล์ตั้งค่า** — คอนเทนเนอร์ถูกตั้งค่าด้วยสิ่งที่ใช้เปิดมัน
"ไปแก้ไฟล์ใน volume แล้วรีสตาร์ต" ไม่ใช่วิธีบอกว่าอิมเมจควรรันโหมดไหน

**ทำไม autostart เป็นแค่บรรทัดเดียวที่เรียก `rb-desktop`** — ฐานอิมเมจคัดลอกไฟล์ autostart ลง volume
ครั้งแรกแล้วไม่กลับมาดูของในอิมเมจอีก อะไรที่เขียนไว้ตรงนั้นจึงแข็งค้างอยู่ที่วันสร้าง volume

**หน้าต่างก็ต้องรับสัญญาณหยุดเหมือน daemon** — ในคอนเทนเนอร์ไม่มีใครนั่งตอบ "แน่ใจไหม"
จึงไม่ผ่านการปิดหน้าต่างแบบปกติซึ่งถาม แต่หยุด core แล้วออกด้วย `exit()` (ไม่ใช่ `quit()`
เพราะ `quit()` เปิดโอกาสให้ทุกหน้าต่างปฏิเสธ)

### เลือก rclone ตอนเริ่ม ไม่ต้อง build ใหม่

`RB_RCLONE_REPO` · `RB_RCLONE_VERSION` — ดาวน์โหลดครั้งเดียว เก็บไว้ใน `/config/.rclone-bin`
ลำดับ: ตัวที่ mount ที่ `/opt/rclone` → ตัวที่ขอผ่านตัวแปร → ตัวในอิมเมจ

`/usr/bin/rclone` เป็นแค่ลิงก์ไปหาตัวที่ใช้อยู่ ส่วนตัวในอิมเมจย้ายไปอยู่ที่ `/usr/lib/rclone-bundled`
และไม่ถูกแตะเลย **ทุกทางที่พลาดจึงจบที่ rclone ที่มากับอิมเมจพร้อมบรรทัดบอกเหตุผล ไม่มีทางจบที่ไม่มี rclone**

**ทำไมไม่ใช้ชื่อ `RCLONE_REPO` / `RCLONE_VERSION`** — rclone อ่าน `RCLONE_<FLAG>` จาก environment
เป็น flag นั้น `RCLONE_VERSION=1.75.0` ในคอนเทนเนอร์จึงทำให้**ทุกคำสั่ง rclone ล้ม**ด้วย
`invalid argument "1.75.0" for "--version"` ลองแล้วเป็นจริง

ตรวจแล้ว: ไม่ตั้งอะไร → ตัวในอิมเมจ · mainline 1.75.0 → ดาวน์โหลดและตรวจ checksum · เปิดซ้ำ → ไม่ดาวน์โหลดอีก ·
เวอร์ชันที่ไม่มีจริง → เตือนแล้วใช้ตัวในอิมเมจ · `latest` ที่ตรงกับอิมเมจ → ไม่ดาวน์โหลด ·
ตั้งแค่เวอร์ชัน → ใช้ repo ของอิมเมจ · tgdrive 1.73.1 ไม่มี checksum ให้ตรวจ → เตือนแล้วใช้

### บั๊กที่ compose สำหรับพัฒนาจับได้

เปิดโหมด `web` กับ volume ใหม่และ `rclone.conf` ของเครื่อง: `docker exec … rclone listremotes`
เห็นรีโหมดครบ 7 ตัว แต่ **API ตอบว่ามี 0 ตัว และเวอร์ชัน rclone ว่าง**

เพราะ**หน้าต่างเป็นคนเดียวที่ออกไปหา rclone บน PATH ตอนยังไม่มีใครตั้งค่า** และเป็นคนเดียวที่ถาม
เวอร์ชัน daemon บนการติดตั้งใหม่จึงไม่มี rclone เลย: ไม่เห็นรีโหมด และทุกงานจะล้มด้วยชื่อโปรแกรมว่าง
**ในคอนเทนเนอร์นี่คือกรณีปกติ ไม่ใช่กรณีแปลก** — รูปเดียวกับสคริปต์และรีโหมดก่อนหน้า:
ความสามารถย้ายมาแล้ว สายไฟยังไม่ได้ต่อ · ย้ายทั้งสองอย่างไป `AppCore::start()` แล้ว

### จอดำ "WebSocket disconnected" — ผู้ใช้เจอตอนเปิดดูครั้งแรก

สคริปต์เตรียม volume เคยอยู่ใน `/etc/cont-init.d` ซึ่ง**รันก่อนทุกอย่าง รวมทั้งก่อนที่ฐานอิมเมจ
จะเปลี่ยนเลขของผู้ใช้ `abc` ตาม `PUID`** — `chown -R abc` จึงยก volume ให้เลข 911 แล้วครู่ต่อมา
`abc` กลายเป็น 1000 ตัวเสียง (pulseaudio) เปิดโฟลเดอร์ของตัวเองไม่ได้ ตัวสตรีมรอไฟล์ pid ของมัน
ไปตลอดกาล หน้าเว็บจึงโหลดได้แต่ต่อ websocket ไม่ติด

**ที่ผมตรวจแล้วไม่เจอ เพราะตอนลองไม่ได้ตั้ง `PUID`** ค่าเริ่มต้น 911 ตรงกันพอดีจึงไม่มีอะไรผิด
compose ตั้ง `PUID=1000` และพังทันที ตอนนี้เป็นบริการ `init-rclonebrowser` ที่ผูกกับ `init-config`
จึงรันหลังเลขผู้ใช้ถูกตั้งแล้ว · หลังแก้: pulseaudio, Selkies และหน้าต่างขึ้นครบ
และ `/api/websockets` ตอบ 101

### ยังไม่ได้ตรวจ

- **ดูหน้าต่างที่สตรีมด้วยตา** — ยืนยันได้แค่ว่ามีหน้าต่างอยู่บนจอและหน้า Selkies ตอบ 200
  ยังไม่มีใครเปิด browser ดูว่าภาพขึ้น คลิกได้ พิมพ์ภาษาไทยได้
- volume จากอิมเมจ noVNC ตัวเดิม — โครงไดเรกทอรีตรงกัน แต่ยังไม่ได้ลองกับ volume จริง
- `rclone mount` ในคอนเทนเนอร์ · tray icon บน Wayland · arm64
- transfer จริงที่กำลังวิ่งตอน `docker stop`
