# แผน: หน้าเว็บที่บอกรายละเอียด และ API ที่ระบบอื่นอ่าน-เขียนได้

> เขียน 2026-10-12 · ต่อจาก [`WEB-UI.md`](WEB-UI.md) และ [`HTTP-API.md`](HTTP-API.md)

## กติกาที่ตกลงกัน (2026-10-12)

1. **หน้าต่างแสดงอะไรได้ หน้าเว็บต้องแสดงได้ด้วย** ในงานชิ้นเดียวกัน ข้อมูลอยู่ที่ core
   ออกทาง API แล้วสองหน้าจอวาดจากที่เดียวกัน งานที่มีแค่หน้าจอเดียวคืองานที่ยังไม่เสร็จ
2. **ทำทีละอัน** และเมื่อเจออะไรระหว่างทาง **จดลงแผนนี้** ที่หัวข้อ "ที่เจอระหว่างทาง" ไม่แวะทำ
3. **API คือการสั่งงาน RcloneBrowser** — ดู task · สั่งรัน · เพิ่มตารางเวลา · คิว · ประวัติ
   ไม่ใช่ทางผ่านไปหา rclone และไม่ใช่ส่วนอื่น
4. **เอกสาร API สร้างอัตโนมัติและแสดงบนหน้าเว็บ** — ไม่เขียนสเปกด้วยมือ (ดู A3 ที่ปรับแล้ว)

## หน้า Remote: ให้หน้าเว็บทำได้เท่าหน้าต่าง

ผู้ใช้ชี้ (2026-10-12) ว่าหน้าเว็บมีแค่ดูไฟล์ ส่วนแท็บรีโหมดในหน้าต่างมีสิบกว่าคำสั่ง

**ทำไมหน้าเว็บเรียกคำสั่งพวกนี้ไม่ได้:** หลายตัวยังถูกสร้างเป็น `QProcess` ในตัวจัดการปุ่มของหน้าต่าง
ไม่ผ่าน `JobRegistry` จึงไม่มีประวัติ ไม่มี log และไม่มีอะไรนอกจากปุ่มนั้นที่สั่งได้
ต้องย้ายเข้า core (`src/remote_ops.*`) ก่อนทีละตัว แล้วทั้งสองหน้าจอจึงเรียกที่เดียวกัน

**รูปของ API สำหรับคำสั่งพวกนี้:** `POST /remotes/{name}/{คำสั่ง}` พร้อม `{"path": …}`
**ตอบเมื่อ rclone ทำเสร็จ** ไม่ใช่ตอบทันทีว่า "รับเรื่องแล้ว" — คนถามอยากรู้ว่าโฟลเดอร์มีแล้วหรือยัง
ถ้าไม่สำเร็จตอบ 502 พร้อม**ข้อความของ rclone เอง** และ `code` ที่เครื่องอ่านได้ (เริ่มใช้รูป A2 ตรงนี้เลย)

**ตัดสินแล้ว (2026-10-12) — ข้อตัดสินใจ 3: โฟลเดอร์ที่เข้าถึงได้คือโฟลเดอร์ที่ mount มาจากโฮสต์**

- `RB_LOCAL_ROOTS` (หรือ `Settings/apiLocalRoots`) คือรายชื่อโฟลเดอร์ที่หน้าเว็บมองเห็นบนเครื่องที่โปรแกรมรัน
  คั่นด้วย `;` · **อิมเมจ Docker ตั้งเป็น `/media`** ซึ่งคือที่ที่ compose เอาโฟลเดอร์ของโฮสต์มาวาง
  เส้นแบ่งจึงเป็น**สิ่งที่ผู้ใช้เลือกยื่นให้คอนเทนเนอร์เอง**
- **ไม่ได้ตั้ง = ทั้งเครื่อง** สำหรับโปรแกรมที่รันบนโต๊ะโดยเจ้าของดิสก์ (Windows: ทุกไดรฟ์ · อื่นๆ: `/`)
- **ทุก path ถูกแปลงให้เป็นตัวจริงก่อนตัดสิน** รวมลิงก์และ `..` — ลิงก์ในโฟลเดอร์ที่อนุญาตซึ่งชี้ออกไปข้างนอกจึงไม่พาออก
  ตรวจในคอนเทนเนอร์จริงแล้ว: `/etc` · `/config` · `/media/../etc` · ลิงก์ `/media/way-out → /etc` ได้ 403 ทั้งหมด
- **"อยู่นอก" กับ "ไม่มีอยู่" ได้คำตอบเดียวกัน** — อันไหนเป็นอันไหนก็คือข้อมูลเกี่ยวกับดิสก์แล้ว
- **ปลายทางที่ยังไม่มีอยู่ตั้งชื่อได้** ถ้าโฟลเดอร์ที่มันจะไปอยู่ได้รับอนุญาต

**ฟอร์ม Transfer และการเขียน task (2026-10-12)**

คำขอ: *"หน้าอับโหลดดาวโหลดทำเพิ่มให้ครบ จัดการได้ทั้งหมด พร้อมเซฟ task ได้"*

- **task เป็นคำ ไม่ใช่ตัวเลข** — `src/task_json.*` (`TaskJson::Write` · `Read` · `Defaults`)
  `operation: "sync"` · `compare: "checksum"` · `syncTiming: "after"` แทนเลขลำดับในกล่องของหน้าต่าง
  ซึ่งถ้าส่งออกไปจะกลายเป็นคำสัญญา · `Read` เขียนเฉพาะช่องที่ถูกเอ่ยถึง (ใช้ได้ทั้งสร้างและแก้)
  และทำบนสำเนา — คำขอที่ผิดครึ่งทางไม่ทิ้ง task ที่ถูกแก้ไปครึ่งเดียว
- **API**: `GET /tasks` · `/tasks/{id}` (ตอนนี้เต็มทุกช่อง) · `GET /tasks/defaults?type=` ·
  `POST /tasks` → 201 · `PUT /tasks/{id}` · `DELETE /tasks/{id}` (409 ถ้ากำลังรัน) ·
  `POST /tasks/preview` → คำสั่งที่จะรัน (redact แล้ว ไม่บันทึกอะไร)
- **ใช้กฎเดียวกับหน้าต่าง** — `TaskBuilder::Check` · `Create` · ชื่ออัตโนมัติ `_tmp_…` · `ListOfJobOptions::Persist`
  task ที่สร้างจากหน้าเว็บจึงเป็น task เดียวกับที่หน้าต่างจะบันทึก และหน้าต่างเห็นทันที (`tasksListUpdated`)
- **เหตุการณ์ใหม่บน SSE: `tasks`** — หน้าเว็บอ่านรายการใหม่เมื่อ task ถูกสร้าง/แก้/ลบ ไม่ว่าจากหน้าเว็บหรือหน้าต่าง
- **ปลายที่อยู่บนเครื่องถูกตรวจด้วย `LocalFiles::Allowed`** ทั้งตอนสร้างและตอนแก้ → 403 `outside_roots`
  task คือการส่งไฟล์ที่รอเกิด ถ้าไม่ตรวจ การบันทึกแล้วรันจะเป็นทางอ้อม `RB_LOCAL_ROOTS`
- **หน้าเว็บ**: ปุ่ม Upload/Download เปิดฟอร์มเดียวกับหน้าต่าง — แท็บ Settings · Transfer · Extra options ·
  Include · Exclude · Filter · rclone cmd · ช่อง From/To พร้อม Browse (เครื่อง / รีโหมด) ·
  แท็บ Tasks มี New upload task · New download task · Edit · Delete
- **บันทึกก่อนเสมอ** เหมือนปุ่มของหน้าต่าง (Save and Run) — ถ้าบันทึกได้แต่สั่งรันถูกปฏิเสธ
  ฟอร์มจำ id ไว้ กดอีกครั้งคือแก้ task เดิม ไม่ใช่สร้างตัวที่สอง

**ข้อตัดสินใจ 2 — ตัดสินแล้ว (2026-10-12): flag ที่ rclone ตัวนี้มี ลบด้วยรายชื่อต้องห้าม**

คำขอ: *"ช่องเส้นทางพิมมั่วๆได้ · ส่วนของการใส่ออฟชันต่างๆให้เป็น autocomplete หรือตัวเลือก
เพื่อให้ใส่ได้เฉพาะส่วนที่รองรับ"* — ซึ่งตอบคำถามเรื่องความเสี่ยงของ `extra` ไปด้วยในตัว

- **`src/extra_flags.*`** — `ExtraFlags::Check(extra, known, restricted)` สองกฎ:
  1. **ต้องเป็น flag ที่ rclone บนเครื่องนี้มี** (ถามจาก `rclone help flags` ผ่าน `RcloneFlagRegistry` ที่หน้าต่างใช้
     ทำ completion อยู่แล้ว) — สะกดผิด · flag ของ fork อื่น · ลืมใส่ค่า ถูกปฏิเสธพร้อมชื่อ
  2. **ต้องห้ามเสมอ** ไม่ว่า rclone จะมีหรือไม่: `--config` · `--password-command` · `--rc` `--rc-*` ·
     ทุกตัวที่ลงท้าย `-command` · `--metadata-mapper` · `--sftp-ssh` · `--log-file` · `--cache-dir` · `--temp-dir` ·
     `--dump*` (เขียน token ลง log ซึ่ง API อ่านได้)
  3. **ต้องห้ามเมื่อ API ถูกจำกัดโฟลเดอร์** (`RB_LOCAL_ROOTS`): `--copy-links` `-L` · `--files-from*` ·
     `--include-from` `--exclude-from` `--filter-from` · `--backup-dir` · `--compare-dest` · `--copy-dest`
     — แต่ละตัวอ่านหรือเขียนที่อื่นบนเครื่อง จึงเป็นทางอ้อมเส้นแบ่งนั้น
- **ถ้าถาม rclone ไม่ได้** (รายการว่าง) ตรวจเฉพาะข้อต้องห้าม — คำถามที่ไม่ได้คำตอบต้องไม่กลายเป็นการปฏิเสธทุกอย่าง
- **ใช้กับการเขียนผ่าน API เท่านั้น** หน้าต่างยังพิมพ์อิสระ (คนที่นั่งหน้าเครื่องเปิด terminal ได้อยู่แล้ว)
  และตัวเลือกเริ่มต้นใน Preferences ไม่ถูกตรวจ · ตอนแก้ task ตรวจ `extra` เฉพาะเมื่อมันถูกเปลี่ยน
- **รายชื่อต้องห้ามเป็นการตัดสิน ไม่ใช่ข้อพิสูจน์** — อยู่ที่เดียวเพื่อให้อ่านและเพิ่มได้ · เมื่อมี API key (A4)
  สิทธิ์เขียน task ก็ยังควรเป็น scope แยก
- **ปลายของ task ถูกตรวจกับของจริง** (`endsProblem` ใน `api_server.cpp`): ปลายฝั่งรีโหมดต้องขึ้นต้นด้วย
  รีโหมดที่มีอยู่ → 400 `no_such_remote` · สิ่งที่ upload ต้องมีอยู่ → 400 `no_such_path`
  ปลายที่ไม่ได้ถูกแตะตอนแก้ไม่ถูกตัดสินซ้ำ (task ที่รีโหมดหายไปแล้วยังเปลี่ยนชื่อได้)
- **ช่องตัวเลขถูกตรวจรูป** ใน `TaskJson::Read`: transfers · checkers · retries · timeout เป็นจำนวนเต็ม ·
  min-size เป็นขนาด · min/max-age เป็นช่วงเวลาหรือวันที่ · bandwidth เป็นอัตราหรือตารางเวลาของ rclone
- **API ใหม่**: `GET /rclone/flags` (รายการ flag ที่เลือกได้ + `loaded`) · `GET /local/stat?path=` (มีอยู่ไหม เป็นโฟลเดอร์ไหม)
- **หน้าเว็บ**: ปลายฝั่งรีโหมดเป็น**ตัวเลือกรีโหมด + path** (พิมพ์ชื่อรีโหมดมั่วไม่ได้) · ปลายฝั่งเครื่องถูกถามขณะพิมพ์
  และบอกใต้ช่อง (a folder / a file / ไม่มีอยู่) · แท็บ Extra options เป็น**ช่องค้นหา flag + ค่า + รายการ**
  แทนกล่องข้อความ · ช่องจำนวนเต็มเป็น `type=number`
- **flag ตามชนิดของรีโหมด** (2026-10-12) — rclone รวม flag ของทุก backend ไว้กลุ่มเดียว (881 จาก 1,043)
  แยกได้จากคำขึ้นต้นเท่านั้น: `ExtraFlags::Backends` · `FlagPrefixOfType` · `WrapsAnother`
  `GET /rclone/flags` มีช่อง `backend` · `GET /remotes` มี `flagPrefix` และ `wraps`
  หน้าเว็บเสนอเฉพาะ flag ทั่วไป + ของ local + ของชนิดรีโหมดที่เลือก (เช่น teldrive: 162 + 17 + 13)
  มีช่องติ๊กให้ดูของชนิดอื่นได้ · แถวที่เป็นของชนิดอื่นมีหมายเหตุว่า rclone จะไม่สนใจ
  **เซิร์ฟเวอร์ไม่ปฏิเสธ** flag ของ backend อื่น: rclone รับได้โดยไม่มีผล และรีโหมดแบบชั้นครอบ
  (crypt · union · alias ฯลฯ) ใช้ flag ของตัวที่อยู่ข้างใต้ด้วย ซึ่งดูจากชนิดไม่ได้ — กรณีนั้นหน้าเว็บเสนอทั้งหมด
  ถ้าจะให้แม่น ต้องอ่านว่าชั้นครอบชี้ไปที่รีโหมดไหนจาก config (ยังไม่ได้ทำ)
- **แก้ของเดิมที่เจอ**: `RcloneFlag::takesValue()` นับ `count` (เช่น `-v`) ว่าต้องมีค่า — completion ของหน้าต่าง
  จึงเติม `--verbose=` ให้ · แก้แล้ว

**เรื่องที่ตัดสินใจตอนทำ Upload · Download**

- **คำสั่งประกอบด้วยโค้ดเดียวกับ task** (`JobOptions::getOptions`) การอัปโหลดจากหน้าเว็บจึงได้
  ตัวเลือกเริ่มต้นของ upload/download จากตั้งค่า เหมือนที่สั่งจากหน้าต่าง
- **เป็นโฟลเดอร์หรือไฟล์ อ่านจากดิสก์** ไม่เชื่อคำของผู้เรียก — มันตัดสินว่าของจะไปอยู่ใต้ชื่อตัวเองไหม
- **ตัวเลือกโฟลเดอร์ตัวเดิมมีโหมดที่สอง** สำหรับเครื่องที่โปรแกรมรัน: เริ่มที่รายการ root · เลือกไฟล์ได้ (สำหรับ upload)
- หน้าเว็บบอกทุกครั้งว่าเป็น**เครื่องที่โปรแกรมรันอยู่** ไม่ใช่เครื่องที่เปิด browser

**Stream — ทำแล้ว (2026-10-12) · ออกทางที่อยู่ของหน้าเว็บ และมีเครื่องเล่นในหน้า**

รอบแรกให้ rclone ฟังพอร์ตของตัวเองแล้วให้โปรแกรมเล่นต่อตรง — ต้องเปิดพอร์ตเพิ่ม (Docker ต้องกันช่วงพอร์ต)
ผู้ใช้ขอ: *"stream ให้ออกไอพีของเว็บเลย จะได้ไม่ต้องเปิดหลายพอต ทำเป็นระบบเครื่องเล่นโมดอลเลยก็ได้"* จึงเปลี่ยน:

- **`rclone serve http` ฟัง `127.0.0.1` พอร์ตว่างใดก็ได้** ไม่มีใครข้างนอกต่อถึง · **API ส่งต่อคำขอให้**
  (`ApiServer::relayStream`) ที่ `/stream/<32 hex>/<ชื่อ>` — พอร์ตเดียวกับหน้าเว็บ ผ่าน reverse proxy/HTTPS ได้เลย
  `RB_STREAM_PORTS` และพอร์ตใน Docker/compose ถูกถอดออก · stream พร้อมกันได้ไม่จำกัด
- **rclone ถูกบอก `--baseurl` เป็น path เดียวกัน** คำขอจึงส่งต่อได้ตามที่มา · ส่งต่อเฉพาะ header ที่โปรแกรมเล่นใช้
  (`Range` ฯลฯ) — **`Authorization` และ `Cookie` ไม่ถูกส่งต่อ** (มี test)
- **ไม่ต้องมี token** เพราะโปรแกรมเล่นส่ง header ไม่ได้ · ส่วนสุ่มของ path คือสิทธิ์ทั้งหมด · stream ที่หยุดแล้วกับที่ไม่เคยมีได้ 404 เหมือนกัน
- **หน่วยความจำถูกจำกัด**: อ่านจาก rclone ทีละไม่เกิน 1 MB และค้างส่งไม่เกิน 4 MB — โปรแกรมเล่นช้ากว่ารีโหมดก็ไม่พอกในโปรแกรม
  (ตรวจจริง: 40 MB ของไฟล์ 604 MB ด้วยผู้อ่านช้า หน่วยความจำ 133 → 146 MB)
- **ไฟล์เดียว**: เสิร์ฟจากโฟลเดอร์ของมันพร้อม `--include /ชื่อ` (escape อักขระของ pattern) — ตรวจจริง: โฟลเดอร์ 158 รายการ เห็นไฟล์เดียว
- **`RedactArgs` ซ่อน `--baseurl`**: คำสั่งที่แสดงไม่มีส่วนสุ่ม · แต่บรรทัด "Serving on …" ใน log ของงานมี (อ่านได้เฉพาะผู้เข้า API ได้)
- **หน้าเว็บ**: ปุ่ม Stream เปิด**เครื่องเล่นในกล่อง** (`<video>`) · โฟลเดอร์ = รายการไฟล์สื่อให้กดเลือก เล่นต่อกันเอง ·
  ยังมีที่อยู่ให้คัดลอก · `.m3u` · ปุ่ม Stop the stream · การ์ดของงานมีปุ่ม Play · หน้าเว็บรอจน rclone ตอบก่อนเปิดเครื่องเล่น
- ⚠ **browser เล่นได้น้อยกว่าโปรแกรมเล่น**: MP4/WebM เกือบเสมอ · MKV บางไฟล์ · เสียง AC3/DTS และภาพ HEVC มักไม่ได้
  หน้าเว็บบอกเมื่อเล่นไม่ได้และชี้ไปที่ที่อยู่สำหรับ VLC — ถ้าจะให้เล่นได้ทุกไฟล์ต้องแปลงสัญญาณฝั่งเครื่อง (ffmpeg) ซึ่งไม่ได้ทำ
- **บั๊กที่เจอจากการลองกับไฟล์จริง**: โปรแกรม**ล้มทั้งตัว** เมื่อโปรแกรมเล่นปิดการเชื่อมต่อกลางคัน (ซึ่งคือทุกครั้งที่เลื่อนตำแหน่ง)
  — socket ฝั่ง rclone เป็นลูกของ socket ฝั่งผู้เล่น และสัญญาณสุดท้ายของมันไปแตะ socket ที่กำลังถูกลบ
  test ชุดแรกผ่านหมดเพราะผู้เล่นใน test อ่านจนจบทุกครั้ง · เพิ่ม test ที่ผู้เล่นทิ้งกลางคัน 3 รอบ (ล้มบนโค้ดเดิม ผ่านบนโค้ดที่แก้)
  แล้วลองจริงซ้ำ: อ่าน · ทิ้ง · เลื่อน · ทิ้ง · เลื่อน — โปรแกรมยังอยู่
- ~~stream ไม่หยุดเอง~~ — **ทำแล้ว** ดู "stream หยุดเอง" · **ที่ยังไม่ได้ทำ**: ยังไม่ได้ดูเครื่องเล่นใน browser จริงและยังไม่ได้เปิดใน VLC · หน้าต่างยังใช้วิธีเดิมของมัน ·
  ปิดหน้าต่างขณะมี stream อยู่ โปรแกรมไม่ปิดภายใน 12 วินาที (น่าจะถามยืนยัน) — ควรดูว่า stream ควรนับเป็น "งานที่กำลังรัน" ตอนปิดไหม

*(บันทึกตอนตัดสินใจ — เก็บไว้)* **Stream: ให้เปิดใน VLC หรือโปรแกรมเล่นอื่นได้**

แนวทาง: เริ่ม `rclone serve http` ของโฟลเดอร์ที่ไฟล์อยู่ เป็นงานชนิด `stream` แล้วให้หน้าเว็บ
- **ที่อยู่ของไฟล์** ที่วางในโปรแกรมเล่นได้ (VLC: Media → Open Network Stream)
- **ไฟล์ `.m3u`** ให้ดาวน์โหลด — เปิดแล้วเด้งเข้าโปรแกรมเล่นที่ตั้งเป็นค่าเริ่มต้น ไม่ต้องพึ่ง `vlc://` ซึ่ง Windows ไม่ได้ลงทะเบียนให้
- **ปุ่มหยุด** = หยุดงาน

ที่ต้องคิดตอนลงมือ: โปรแกรมเล่นส่ง header ไม่ได้ จึงต้องใช้**รหัสของ stream นั้นเองใส่ใน URL**
(สุ่มใหม่ทุกครั้ง หมดเมื่อหยุด) — ต่างจาก token ของ API ที่ห้ามอยู่ใน URL · และใน Docker ต้องเปิดพอร์ตเพิ่ม
(พอร์ตเดียวที่ตั้งได้ เช่น 19998 → stream ได้ทีละอัน หรือช่วงพอร์ต)

**เรื่องที่ตัดสินใจตอนทำ Mount**

- **หน้าต่างทำการ์ดให้ mount ทุกตัว ไม่ว่าใครสั่ง** — เดิมการ์ดถูกสร้างเฉพาะใน `addNewMount()`
  mount ที่มาจากที่อื่น (task ที่รันจากหน้าเว็บ · API · ตารางเวลา · คิว) จึง**ขึ้นอยู่จริงแต่ไม่มีอะไรในหน้าต่าง
  ให้เห็นหรือให้กดถอด** นี่เป็นช่องว่างที่มีอยู่ก่อนงานนี้ ไม่ได้เกิดจากมัน
- **คำสั่งประกอบด้วยโค้ดเดียวกับ task แบบ mount** (`JobOptions::getMountOptions`)
  mount จากหน้าเว็บกับ mount จาก task จึงเป็นคำสั่งเดียวกัน
- **ได้พอร์ต remote control ของตัวเองเสมอ** เพราะบน Windows เป็นทางเดียวที่สั่ง mount ให้ลงได้
  · รหัสเข้าไม่อยู่ในอาร์กิวเมนต์ (มี test ยืนยัน)
- **ตอบทันที (202)** — mount อยู่นานเท่าที่ต้องการ ขึ้นสำเร็จหรือไม่ดูที่งาน
- **หน้าเว็บบอกชัดว่า mount เกิดบนเครื่องที่โปรแกรมรัน** ไม่ใช่เครื่องที่เปิด browser
- **ที่ mount ถูกหรือไม่ ให้ rclone เป็นคนบอก** — ต่างกันตามระบบและสิ่งที่ติดตั้ง (WinFsp · FUSE)

**เรื่องที่ตัดสินใจตอนทำ Check · Export**

- **ความต่างคือคำตอบ ไม่ใช่ความล้มเหลว** — rclone จบ check ด้วย error เมื่อสองฝั่งไม่เหมือนกัน
  ถ้าส่งต่อเป็น 502 จะบอกคนถามว่า "ตรวจไม่ได้" ทั้งที่ตรวจแล้วและเจอ · แยกด้วยว่า rclone
  ไปถึงขั้นนับหรือยัง (`N differences found`) → 200 พร้อม `matched: false` · ตรวจไม่ได้จริงยังเป็น 502
- **ไม่ให้ตรวจโฟลเดอร์กับตัวเอง** — ตรงกันเสมอ และน่าจะเป็นการเลือกผิดมากกว่าคำถาม
- **ไฟล์ export เขียนโดยฟังก์ชันเดียวใน core** ไฟล์ที่หน้าต่างบันทึกกับไฟล์ที่หน้าเว็บดาวน์โหลดจึงเป็นไฟล์เดียวกัน
  · **แก้บั๊กเดิมไปด้วย**: ชื่อไฟล์ที่มี `"` ทำให้แถวของ CSV พัง ตอนนี้ถูก escape
- **ดาวน์โหลดด้วย `fetch` + header แล้วส่งต่อเป็นไฟล์** ไม่ใช้ลิงก์ธรรมดา เพราะลิงก์ต้องมี secret ใน URL
- **listing ใหญ่เกิน 64 MB ตอบ 413** พร้อมบอกให้จำกัดด้วย `maxDepth` — ไม่ตัดไฟล์เงียบๆ
  เพราะไฟล์ export ที่ขาดหายคือไฟล์ที่โกหก

**ผู้ใช้เจอทันทีที่ลอง Copy จากหน้าเว็บ:** คัดลอกไฟล์ภายใน gdrive แล้วรีโหมดนั้นขึ้นงานเดียวกัน
เป็นทั้ง "อัปโหลดครั้งล่าสุด" **และ** "ดาวน์โหลดครั้งล่าสุด" — เพราะนิยามเดิมดูแค่ว่าปลายข้างหนึ่งอยู่บนรีโหมด
ซึ่งพอสำหรับตอนที่ transfer ทุกงานมีปลายข้างหนึ่งอยู่ในเครื่อง แต่ Copy/Move บนรีโหมดมีสองปลายอยู่บนรีโหมดทั้งคู่

นิยามตอนนี้: **อัปโหลดมาจากเครื่องนี้ ดาวน์โหลดมาลงเครื่องนี้** การคัดลอกหรือย้ายภายในรีโหมด
หรือข้ามรีโหมด ไม่ใช่ทั้งสองอย่าง · path ในเครื่องคือ: มีอักษรไดรฟ์ (`C:/…`) · ขึ้นต้นด้วย `/` · หรือไม่มี `:` ก่อน `/` ตัวแรก

**เรื่องที่ตัดสินใจตอนทำ Copy · Move**

- **ตอบทันทีที่เริ่ม (202) ไม่รอจบ** — ต่างจากคำสั่งอื่นในหน้านี้ที่ตอบเมื่อเสร็จ การคัดลอกใช้เวลาตามขนาดไฟล์
  ไม่ควรมีใครถือ connection ค้างไว้ มันเป็น transfer เหมือนงานอื่น: `/jobs` และสายเหตุการณ์บอกความคืบหน้า
- **"คัดลอกเข้าไปใน" ไม่ใช่ "คัดลอกไปเป็น"** — โฟลเดอร์ไปอยู่ใต้ชื่อของตัวเองในปลายทาง
  (`films/2026` → `backup/2026`) เพราะ rclone คัดลอก*เนื้อหา*ของโฟลเดอร์ ถ้าไม่ต่อชื่อของข้างในจะหกลงปลายทางตรงๆ
- **ข้ามรีโหมดได้** ผ่าน API และหน้าเว็บ (`toRemote`) · หน้าต่างยังทำได้แค่ในรีโหมดเดียวกัน
- **ปฏิเสธก่อนเริ่ม**: รากของรีโหมด · โฟลเดอร์เข้าไปในตัวเองหรือในลูกของตัวเอง · ที่ที่มันอยู่แล้ว
- **ตัวเลือกโฟลเดอร์ของหน้าเว็บ** (`pickFolder`) เป็นชิ้นกลาง ใช้ `/ls` ตัวเดียวกับหน้ารายการ
  เปลี่ยนรีโหมดได้ บอกเหตุผลเมื่อเปิดโฟลเดอร์ไม่ได้ — Check และ Upload/Download จะใช้ตัวนี้ต่อ
- **รายการถูกอ่านใหม่เมื่องานจบ** ถ้ายังดูโฟลเดอร์เดิมอยู่

**เรื่องที่ตัดสินใจตอนทำ Link · Cleanup · Dedupe**

- **แชร์รากของรีโหมดไม่ได้** ด้วยเหตุผลเดียวกับการลบ — path ที่เว้นว่างไม่ใช่คำขอให้แชร์ทุกอย่าง
- **Link ถามก่อนทำ** เพราะทำแล้วมองไม่เห็น: ไม่มีอะไรในรายการไฟล์ที่บอกว่าไฟล์ถูกแชร์แล้ว
  · ที่อยู่กลับมาเป็นช่อง `url` ของตัวเอง ไม่ต้องขุดจาก output
- **Dedupe รับเฉพาะโหมดที่รู้จัก** (skip · first · newest · oldest · largest · smallest · rename)
  โหมดอื่นถูกปฏิเสธ เพราะถ้าส่งต่อไป rclone จะไป**ถามที่ terminal ที่ไม่มีใครนั่งอยู่**
- **Dedupe ผ่าน API ไม่รับ flag เพิ่ม** — หน้าต่างมีช่องให้พิมพ์ คำขอทาง HTTP ไม่มี ด้วยเหตุผลเดียวกับ task
- **หน้าเว็บวางปุ่ม Dry run ไว้ก่อน Run for real** และ dry run ถูกจดในประวัติว่าเป็นการซ้อม
- **Cleanup ใช้ถ้อยคำเดียวกับหน้าต่าง** เพราะชื่อไม่บอกว่ามันทำอะไร และต่างกันไปตาม backend

**เรื่องที่ตัดสินใจตอนทำ Size · Info · Tree**

- **เป็น `GET`** เพราะไม่เปลี่ยนอะไร และตอบเมื่อ rclone ตอบ เหมือน `/ls`
- **API ตอบเป็นตัวเลข หน้าต่างยังแสดงเป็นข้อความ** — คำสั่งเดียวกันจาก core ต่างกันที่ `--json`
  โปรแกรมอื่นที่ถามว่าโฟลเดอร์ใหญ่แค่ไหนต้องการจำนวนไบต์ ไม่ใช่ประโยค
- **แสดงเฉพาะตัวเลขที่ backend รายงาน** — Google Drive ให้ครบ (total · used · free · trashed · other)
  teldrive ให้แค่ `used` · ตัวเลขที่ไม่มีไม่ใช่ศูนย์
- **คำถามใช้กับแถวที่เลือก ถ้าไม่ได้เลือกใช้โฟลเดอร์ที่กำลังดู**
- **คนถามหายไป งานถูกหยุด** — `size` ของรีโหมดใหญ่ใช้เวลาเป็นนาที

**เรื่องที่ตัดสินใจตอนทำ Rename และ Delete**

- **Rename รับชื่อ ไม่รับ path** — ของอยู่ที่เดิม ได้ชื่อใหม่ การย้ายไปที่อื่นเป็นอีกคำสั่งและอีกคำถาม
  ชื่อเดิมถูกปฏิเสธก่อนเริ่ม เพราะ rclone จะย้ายของทับตัวเองแล้วรายงานว่าสำเร็จ
- **ไฟล์ลบด้วย `deletefile` ไม่ใช่ `delete`** — หน้าต่างเคยใช้ `delete` ซึ่งถ้าเจอโฟลเดอร์จะ
  **ลบทุกไฟล์ข้างใต้เงียบๆ** `deletefile` ปฏิเสธโฟลเดอร์ คำขอที่บอกว่า "ไฟล์" กับของที่เป็นโฟลเดอร์
  จึงจบที่ข้อผิดพลาด ไม่ใช่โฟลเดอร์ที่ถูกกวาด · ผ่าน API ถ้าไม่บอกว่าเป็นโฟลเดอร์ ถือว่าเป็นไฟล์
- **ลบรากของรีโหมดไม่ได้** ไม่ว่าจะสะกด path ว่างแบบไหน — ช่องที่เว้นว่างไม่ใช่คำขอให้ลบทุกอย่าง
- **กล่องยืนยันในหน้าเว็บบอกชื่อเต็มของสิ่งที่จะหาย** และบอกว่าโฟลเดอร์พาของข้างในไปด้วย

**Upload/Download (ข้อ 12) ใหญ่กว่าตัวอื่นมาก** เพราะสองเรื่อง:
- browser เลือกไฟล์ในเครื่องที่ daemon รันอยู่ไม่ได้ ต้องมี **API เดินดูโฟลเดอร์ฝั่ง daemon**
  ซึ่งต้องถูกจำกัดด้วยรายชื่อโฟลเดอร์ที่อนุญาต (ข้อตัดสินใจ 3)
- กล่อง Transfer มีตัวเลือกราว 45 อย่าง และจบด้วยการสร้าง task — คืองานเดียวกับ A5 ข้อ 3

## ตารางเวลา: เอา task เข้าตารางเวลาจากหน้าเว็บ (2026-10-12)

คำขอ: *"ดูเรื่องตารางเวลาต่อ การเอา task เข้าตารางเวลา"* — คือ A5 ข้อ 1

- **ตารางเวลาเป็นคำ** — `src/schedule_json.*`: `mode: daily|cron` · `days: [mon…sun]` · `time: "06:30"` · `cron` ·
  `runAs: now|queue` · `active` แทน boolean เก้าตัวกับเลขโหมดที่ storage เก็บ · `Read` เขียนเฉพาะที่เอ่ยถึง ทำบนสำเนา
  และปฏิเสธสิ่งที่**ไม่มีวันถึงกำหนด**: daily ที่ไม่มีวัน · เวลาที่ไม่มีจริง · cron ที่อ่านไม่ออก (ตรวจด้วย qcron ตัวเดียวกับนาฬิกา)
- **API**: `POST /schedules` → 201 · `PUT` · `DELETE /schedules/{id}` · `POST /schedules/{id}/enable|disable` ·
  `POST /scheduler/start|pause` (สวิตช์ของทั้งระบบ) · `GET /schedules` ตอนนี้เต็มทุกช่อง
- **ต้องชี้ไปที่ task ที่มีอยู่ และไม่ใช่ mount** (หน้าต่างก็ไม่ให้) · ไม่ตั้งชื่อ = ใช้ชื่อ task
- **ลบ task ที่มีตารางเวลาไม่ได้** → 409 `scheduled` บอกชื่อตารางเวลา (ปิดข้อ "ลบ task แล้วตารางเวลากำพร้า" ที่จดไว้)
- **ไม่เสี่ยงแบบ task**: ตารางเวลาไม่มีคำสั่งของตัวเอง อย่างมากคือรัน task ที่มีอยู่แล้วผิดเวลา
- **หน้าเว็บ**: แท็บ Schedules มี New schedule · Switch on/off · Edit · Delete · Run now · ปุ่ม Start/Pause the scheduler ·
  คอลัมน์ When เป็นภาษาคน ("Mon–Fri at 06:30") · แท็บ Tasks มีปุ่ม **Schedule** บนการ์ด และบรรทัด ⏱ บอกว่า task นั้นมีตารางเวลาอะไร
- **เหตุการณ์ `schedule` บน SSE** ส่งเมื่อที่เก็บเปลี่ยนด้วย หน้าเว็บจึงตามหน้าต่าง

⚠ **กับดักครึ่งย้าย — เจอและแก้**: หน้าต่างถือตารางเวลาเป็นการ์ดบนแท็บ และทุกครั้งที่แก้การ์ดใดก็**เขียนการ์ดทั้งหมดทับที่เก็บ**
(`saveSchedulerFile` → `setAll`) ตารางเวลาที่สร้างจากหน้าเว็บจึงอยู่ในที่เก็บแต่ไม่อยู่บนแท็บ และจะ**ถูกลบเงียบๆ** ตอนแก้การ์ดครั้งถัดไป
แก้: `MainWindow::followSchedulerStore()` — เมื่อที่เก็บเปลี่ยนโดยไม่ใช่หน้าต่างเอง เทียบ "ตารางเวลาคืออะไร" (task · เวลา · เปิดปิด)
ถ้าต่างก็สร้างการ์ดใหม่จากที่เก็บ · สวิตช์ของทั้งระบบก็ตามด้วย · สิ่งที่นาฬิกาเขียนตลอดวัน (ผลรอบล่าสุด) ไม่นับเป็นความต่าง
**ยังไม่ได้ดูด้วยตา** — ตรวจได้แค่ว่าโปรแกรมไม่ล้มและตารางเวลาไม่หายหลังหน้าต่างมีเวลาตอบสนอง

ที่จดไว้:
- การสร้างการ์ดใหม่ทั้งแท็บ**ทิ้งการแก้ที่ค้างอยู่บนการ์ด** (ยังไม่กด Save) และการ์ดที่รอบกำลังรันจะขึ้นสถานะ `unknown`
  (พฤติกรรมเดิมตอนเปิดโปรแกรม) ทางที่ถูกคือให้การ์ดอ่านจากที่เก็บตรงๆ — งานของ SCHEDULER-MOVE
- ตารางเวลาที่ task หายไปแล้วไม่ขึ้นบนแท็บของหน้าต่าง แต่ขึ้นบนหน้าเว็บ (ลบได้จากเว็บ)
- เวลาเป็นนาฬิกาของเครื่องที่โปรแกรมรัน หน้าเว็บบอกไว้ในฟอร์ม · `nextRun` ยังไม่มี offset ของเขตเวลา (A2)

## คิว: เรียงลำดับและล้างจากหน้าเว็บ (2026-10-18)

- หน้าต่างใช้ `JobQueue` ของ core อยู่แล้ว (ย้ายไว้ก่อนหน้า) และวาดแท็บใหม่ทุกครั้งที่คิวเปลี่ยน — **ไม่มีกับดักแบบตารางเวลา**
- **API**: `POST /queue/{requestId}/move` `{"to": 2}` หรือ `"up"` `"down"` `"top"` `"bottom"` · `POST /queue/clear` → `{removed, queued}`
- **ตัวที่กำลังรันอยู่หัวคิวเสมอ**: ย้ายตัวมันไม่ได้ และย้ายตัวอื่นขึ้นไปแทนที่ไม่ได้ (409) · ล้างคิวแล้วตัวที่รันอยู่ทำงานต่อ
- ขอให้ไปที่ที่อยู่แล้ว (top ตอนอยู่บนสุด) = 200 ไม่ใช่ error
- **หน้าเว็บ**: แท็บ Queue มีลำดับ # · ปุ่ม ⤒ ↑ ↓ ⤓ · Remove · **Clear the queue** (ถามยืนยัน) · ปุ่มเริ่ม/หยุดคิวพร้อมคำอธิบายสถานะ
- ~~เอาออกผ่าน API แล้วตารางเวลาไม่รู้~~ — **แก้แล้ว (2026-10-18)**: `JobQueue` ส่งสัญญาณ `removed(requestId)` เมื่อรายการถูกเอาออก
  ก่อนรัน (ทั้ง remove และ clear ไม่ว่าจากที่ไหน) · `AppCore` บันทึก "removed from the queue" ลงตารางเวลาในที่เก็บ ·
  หน้าต่างบอกการ์ดจากสัญญาณเดียวกัน แทนที่ปุ่มสามปุ่มของมันจะบอกเอง (ไม่นับซ้ำ)

## เอกสาร API อัตโนมัติ (2026-10-18)

กติกาข้อ (d): *"api แบบออโต้ แสดงบนหน้าเว็บ"*

- **`src/api_routes.*`** — รายการเส้นทางทั้งหมด 61 รายการ (method · path · หมวด · สรุป · คำอธิบาย · query · ตัวอย่าง body · ความหมายของแต่ละ status · เปิดโดยไม่ต้องมี token ไหม)
- **`GET /api/v1/openapi.json`** — OpenAPI 3.1 สร้างจากรายการนั้น · **ไม่ต้องมี token** (เครื่องมืออย่าง Swagger/Postman อ่านก่อนมี key และไม่มีข้อมูลของเครื่องนี้ — มี test ว่าไม่มี token อยู่ในนั้น) · version จากไฟล์ `VERSION`
- **แท็บ API บนหน้าเว็บ** — วาดจาก openapi.json: แยกหมวด · กดเปิดดูรายละเอียด · ช่องกรอง · ปุ่ม **Try it** สำหรับ GET ที่ไม่ต้องกรอกอะไร · ลิงก์ openapi.json
- **กันรายการเพี้ยนจากโค้ด**: ทุกคำขอที่เข้ามาถูกค้นในรายการ ถ้าไม่เจอจะถูกจดไว้ (`ApiRoutes::Unlisted`) และ test ของ API
  จบด้วยการตรวจว่า**ทุกคำขอที่ test ส่งอยู่ในรายการ** ยกเว้นคำขอมั่วที่ตั้งใจ (`GET /api/v1/nothing`)
  **ลองแล้วว่าจับได้จริง**: เอา `POST /queue/clear` ออกจากรายการ → test ล้ม "not in ApiRoutes: POST /api/v1/queue/clear"
- ⚠ **ขอบเขตของการกัน**: จับได้เฉพาะเส้นทางที่ test เรียก — เส้นทางที่ไม่มี test เลยจะเพี้ยนได้โดยไม่มีใครรู้
  และ**คำอธิบาย/status ในรายการยังเขียนด้วยมือ** ตรวจได้แค่ว่าเส้นทางมีอยู่ ไม่ได้ตรวจว่าคำอธิบายถูก
- ยังไม่มี schema ของคำตอบ (มีแค่ตัวอย่าง body ของคำขอ) — A2 (รูปแบบที่ตกลงกัน) ต้องมาก่อน
- แก้ของเดิมที่เจอ: ปุ่มเปลี่ยนแท็บไปเปลี่ยนสถานะของแถบแท็บในฟอร์ม Transfer ด้วย (selector `nav button` กว้างเกิน) → `#tabs button`
- `docs/HTTP-API.md` ยังเป็นคำอธิบายเชิงเหตุผล ส่วนรายการเส้นทางที่ถูกต้องที่สุดคือ openapi.json

## API key แบบจำกัดสิทธิ์ (2026-10-18)

- **`ApiAuth::Keys`** — key มีชื่อ · ระดับ · สร้างเมื่อ · ใช้ล่าสุดเมื่อ · รูป `rbk_<id 8 hex>_<ความลับ 43 ตัว>`
  เก็บใน `Settings/apiKeys` **เฉพาะ hash (SHA-256) ของความลับ** — ตัว key แสดงครั้งเดียวตอนสร้าง (ตรวจในเครื่องจริงแล้วว่าไม่อยู่ใน registry)
  ใช้ SHA-256 ไม่ใช่ PBKDF2 เพราะความลับสุ่ม 32 ไบต์เดาไม่ได้ และต้องตรวจทุกคำขอ · id ในตัว key ทำให้ตรวจ hash ครั้งเดียวต่อคำขอ
  "ใช้ล่าสุด" เขียนลงที่เก็บอย่างมากนาทีละครั้ง · ชื่อซ้ำไม่ได้ (ไม่สนตัวพิมพ์) เพราะประวัติใช้ชื่อบอกว่าใครสั่ง
- **ระดับ**: `read` ดู · `control` + รัน/เข้าคิว/หยุด/เปิดปิดคิวและตารางเวลา/stream/mount · `write` + สร้างแก้ลบ task ตารางเวลา และเปลี่ยนไฟล์บนรีโหมด · `admin` ทุกอย่าง (token และ session ของ admin คือระดับนี้)
- **ระดับที่แต่ละเส้นทางต้องการอยู่ในรายการเส้นทาง** (`ApiRoutes`, `x-scope` ใน openapi.json และป้ายบนแท็บ API) — ไม่ได้เขียนกระจายในโค้ด
  กติกา: GET = read · ที่เหลือ = write ยกเว้นรายการ control / read / admin ที่ระบุชื่อ
- **ปิดเมื่อไม่รู้**: เส้นทางที่ไม่อยู่ในรายการต้องการ admin — key ระดับต่ำกว่าได้ 403 ไม่ใช่ผ่าน
- **403 `insufficient_scope`** พร้อม `needs` บอกระดับที่ต้องการ
- **ประวัติบอกว่า key ไหนสั่ง**: task ที่รันผ่าน key มี `startedBy: "api:<ชื่อ key>"` (เฉพาะ run โดยตรง — ที่เข้าคิวยังขึ้น "queue")
- **API**: `GET /keys` · `POST /keys` `{name, scope}` → 201 พร้อม key ครั้งเดียว · `DELETE /keys/{id}` — ทั้งหมดต้องเป็น admin
- **หน้าเว็บ**: กล่อง "Keys for other programs" บนสุดของแท็บ API — รายการ · สร้าง (แสดง key ครั้งเดียวพร้อมปุ่ม Copy) · Take back
  key ใช้ sign in หน้าเว็บได้ในช่อง Token ด้วย (ปุ่มที่ทำไม่ได้จะได้ข้อความ 403)
- ยังไม่ได้ทำ: key ไม่มีวันหมดอายุ · ไม่จำกัดว่ามาจาก IP ไหน · ไม่มีหน้าจัดการ key ในหน้าต่าง (มีเฉพาะเว็บและ API)

## stream หยุดเองเมื่อไม่มีใครเล่น (2026-10-18)

- ทุกการเล่นผ่านตัวส่งต่อของ API (`relayStream`) จึงนับได้ว่า**มีผู้เล่นต่ออยู่กี่ราย**และ**มีข้อมูลผ่านล่าสุดเมื่อไร**
- stream ที่**ไม่มีผู้เล่นต่ออยู่เลย**และเงียบเกินกำหนด → หยุดเอง (สถานะ stopped ในประวัติ) · การเริ่มนับเป็นการใช้ ดังนั้น stream ที่ไม่มีใครเปิดเลยก็หยุดเองเช่นกัน
- **ผู้เล่นที่ต่ออยู่ไม่ถูกตัด แม้กด pause นาน** — โปรแกรมเล่นค้างการเชื่อมต่อไว้ระหว่าง pause
- กำหนด: `RB_STREAM_IDLE_MINUTES` หรือ `Settings/streamIdleMinutes` · ค่าเริ่มต้น **30 นาที** · `0` = ไม่หยุดเอง
- หน้าเว็บบอกในกล่องเครื่องเล่นว่าจะหยุดเองหลังกี่นาที · งานมี `stream.stopsWhenIdleFor` (วินาที)
- ตรวจจริงแล้ว: ตั้ง 1 นาที เล่นครั้งเดียวแล้วทิ้ง → หยุดเองที่ 70 วินาที ไม่มี rclone ค้าง
- ⚠ โปรแกรมเล่นบางตัวปิดการเชื่อมต่อระหว่าง pause (โดยเฉพาะ browser ที่ buffer ไว้ครบแล้ว) — pause นานเกินกำหนดแล้วกดเล่นต่อจะได้ 404 ต้องกด Stream ใหม่
- ยังไม่ได้ทำ: การตั้งค่านี้ยังไม่มีในหน้าต่าง Preferences หรือหน้าเว็บ

## ที่เจอ (2026-10-18): สถานะรอบล่าสุดของตารางเวลา core ไม่ได้บันทึกเลย

ระหว่างแก้เรื่องคิว: `lastRun` · `lastFinished` · `lastStatus` ของตารางเวลา **ถูกเขียนโดยการ์ดในหน้าต่างเท่านั้น**
(การ์ดได้ข่าวจากงาน แล้วหน้าต่างบันทึกการ์ดทั้งหมดลงที่เก็บ) — core ตั้งแค่ `requestId` ตอนสั่งรัน
ผลคือ**ถ้ารันแบบ daemon (Docker โหมด web) คอลัมน์ Last ในหน้าเว็บไม่เปลี่ยนเลย** และแม้มีหน้าต่าง ค่าที่หน้าเว็บเห็นก็ขึ้นกับว่าหน้าต่างบันทึกเมื่อไร
นี่คือกับดักครึ่งย้ายอีกตัว

**แก้แล้ว (2026-10-18)** — `AppCore` บันทึกเองลงที่เก็บ ไม่ต้องมีหน้าต่าง:
- ตอนสั่งรัน: `lastRun` = ตอนนี้ · `lastStatus` = running หรือ in the queue · ล้าง `lastFinished`
- ตอนรอบที่เข้าคิวได้เริ่ม (`JobRegistry::jobStarted`): running
- ตอนจบ (`jobFinished`): finished · error · stopped และ `lastFinished`
- ตอนไม่ได้รัน (held): เหตุผลเป็น `lastStatus` เช่น "its last run has not finished" · เอาออกจากคิว: "removed from the queue"
- ใช้รูปเวลาเดียวกับการ์ด (`ScheduleStamp`: "Sun, 18/Oct/2026 22:54:32 GMT+7") และคำเดียวกับการ์ด
- การ์ดในหน้าต่างยังบันทึกของมันเองด้วย (ข้อมูลเดียวกันจากเหตุการณ์เดียวกัน) — ยังไม่ได้เปลี่ยนให้การ์ดอ่านจากที่เก็บ
- ~~เปิดโปรแกรมใหม่แล้ว in the queue กลายเป็น unknown~~ — **แก้แล้ว (2026-10-18)**: `AppCore::reconcileSchedules()` ตัดสินครั้งเดียวหลังอ่านที่เก็บและคิว —
  รอบที่ยังอยู่ในคิว = in the queue · ที่กำลังรัน = running · นอกนั้น = unknown · การ์ดใช้กฎเดียวกันตอนถูกสร้าง
  **ตรวจกับของจริง**: ตารางเวลา OneDrive ที่รออยู่ในคิว เปิดโปรแกรมใหม่แล้วยังเป็น in the queue (ก่อนแก้จะเป็น unknown)
- **พร้อมกัน**: แสดงสถานะ "หยุด" ของ scheduler ตอนเปิดโปรแกรมหรือเพราะหน้าเว็บสั่ง**ไม่ยกเลิกรอบที่รออยู่แล้ว** (`stopScheduler(false)`)
  — ก่อนหน้านี้ไม่เคยเกิดเพราะสถานะถูกล้างเป็น unknown ก่อน · ปุ่ม Stop scheduler ของหน้าต่างยังยกเลิกเหมือนเดิม
  ⚠ จึงต่างกันอยู่: หยุด scheduler จากหน้าต่าง = ยกเลิกรอบที่รอ · จากหน้าเว็บ/API = ไม่ยกเลิก (แบบเดียวกับ core) ควรตัดสินว่าแบบไหนถูก
- ข้อสังเกต: `GET /schedules` ไม่ได้ส่ง `requestId` ของรอบล่าสุด จึงบอกไม่ได้จากภายนอกว่ารายการไหนในคิวเป็นของตารางเวลาไหน

## ตัวช่วยสำรองข้อมูล (2026-10-19)

- **core**: `BackupPlan` (อะไร · ไปไหน · mirror หรือเก็บทุกอย่าง · เก็บเวอร์ชันเก่า · วัน · เวลา) → `Backup::Build` ได้ task + schedule
  ที่ยังไม่บันทึก (ให้ API ตรวจขอบเขตโฟลเดอร์ก่อน) → `Backup::Save` (TaskBuilder::Create + SchedulerStore) · **ไม่มีอะไรใหม่ที่รัน backup**
  เป็น task ธรรมดาบนตารางเวลาธรรมดา (ผ่านคิว)
- **เวอร์ชันเก่า**: `--backup-dir "<dest>-versions/{date}"` · **`{date}` ใหม่** ใน extra options ของทุก task = เวลาของรอบนั้น
  (rclone ไม่มีของแบบนี้ และ task เป็นคำเดิมทุกรอบ) · ข้างๆ ไม่ใช่ข้างใน: ข้างในรอบต่อไปจะ backup เวอร์ชันด้วย และ mirror จะลบมัน
- **API**: `POST /backups` (write) · `--backup-dir` ปกติห้ามเมื่อ API ถูกจำกัดโฟลเดอร์ แต่ที่นี่โปรแกรมสร้างเอง จึงตรวจโฟลเดอร์ versions ตรงๆ แทน
- **หน้าเว็บ**: แท็บ Tasks → **New backup…** · **หน้าต่าง**: File → **New backup…** (`BackupDialog` มีปุ่มเลือกโฟลเดอร์)
- **ตรวจกับ rclone จริง** (โฟลเดอร์ในเครื่อง): sync + `--backup-dir` ข้างๆ → ไฟล์ที่เปลี่ยน (v1) และที่ลบ ย้ายไป `dst-versions/<date>/` ·
  backup-dir ข้างใน dest → rclone ปฏิเสธว่า overlap (ยืนยันว่าต้องข้างๆ)
- ยังไม่ได้: ลบเวอร์ชันเก่าที่เกินอายุ (rclone delete --min-age บนโฟลเดอร์ versions) · remote → remote · ลองกับของจริงตามตารางเวลา

- **ครั้งแรกต้อง `--resync`** (rclone ไม่รู้จักคู่นี้ → exit 7 "Must run --resync to recover") · `resync` **ไม่เก็บกับ task**
  แบบเดียวกับ dryRun — ถ้าเก็บ ทุกรอบตามตารางเวลาจะเริ่มคู่ใหม่ · `StartTask(..., resync)` ตั้งแล้วล้างทันทีหลังสร้างคำสั่ง
- **API**: `POST /tasks/{id}/run {"resync":true}` · task ที่ไม่ใช่ bisync → 400
- **หน้าเว็บ**: ตัวเลือก Bisync ในฟอร์ม task (ตัวเลือกการลบของ sync ซ่อน) · การ์ด task มีปุ่ม **First run (resync)**
- **หน้าต่าง**: ตัวเลือก Bisync ในกล่อง transfer · คลิกขวา task → **Run first time (resync)**
- **ตรวจกับ rclone v1.73.1 จริง** (โฟลเดอร์ทดสอบในเครื่อง พร้อม flag ที่ task เติม `--rc` `--stats-log-level` `--stats`):
  ไม่ resync → exit 7 · resync → สองฝั่งรวมกัน · เพิ่มไฟล์ฝั่ง b + ลบฝั่ง a → ทั้งสองฝั่งตรงกัน · ลบโฟลเดอร์และ listing ทดสอบแล้ว
- ⚠ Windows: listing ของ bisync อยู่ที่ `%LOCALAPPDATA%/rclone/bisync/<path1>..<path2>.lst` — path ยาวมากเกิน MAX_PATH แล้ว bisync ล้ม
  ("syntax error detected in your path(s)")
- ยังไม่ได้: บอกในหน้าเว็บ/หน้าต่างเมื่องานล้มเพราะต้อง resync (ตอนนี้อยู่ใน log) · ตัวเลือกของ bisync เอง (`--conflict-resolve`, `--max-delete`, `--resilient`)

## ดูไฟล์ในตัว (2026-10-19)

- **core**: `FileReader` (แบบ `DirectoryListing` — เป็นคำถาม ไม่ใช่งาน ไม่มีแถวประวัติ) `rclone cat --count limit+1` ·
  `ViewOf(name)` → image/pdf/text/media/"" จาก `QMimeDatabase` · `TypeOf(name)`
- **API**: `GET /remotes/{name}/cat` ตอบเป็น octet-stream เสมอ + `X-Rb-View/Type/Truncated` · ภาพ/PDF ทั้งไฟล์ (≤ 64 MiB) · อื่นๆ 2 MiB แรก
- **ความปลอดภัย**: หน้าเว็บส่ง token ทาง header เท่านั้น — `<img>`/frame ส่งไม่ได้ จึง fetch แล้วแสดงจาก blob ·
  **HTML/SVG ไม่ถูกแสดงเป็นหน้าเด็ดขาด** (blob ของหน้าเรามี origin เดียวกับหน้าเรา สคริปต์ในไฟล์จะอ่าน token ได้) — HTML เป็นข้อความ · SVG ใน `<img>` ที่สคริปต์ไม่รัน
- **หน้าเว็บ**: ปุ่ม **View** (ไฟล์ที่เลือก) และ**ดับเบิลคลิกไฟล์** · ภาพ · PDF ใน frame · ข้อความใน `<pre>` (บอกเมื่อเห็นแค่ส่วนต้น) ·
  เพลง/วิดีโอ → ปุ่ม Play it (stream) · ชนิดอื่น → "Show it as text anyway" · ปล่อยหน่วยความจำเมื่อปิด
- **หน้าต่าง**: **View** ในเมนูคลิกขวา และ**ดับเบิลคลิกไฟล์** (`FileViewDialog` ผ่าน `FileReader` ตัวเดียวกัน ค่าจำกัดเดียวกัน) ·
  ภาพ · ข้อความ ในกล่องเอง · PDF (และภาพที่ Qt วาดไม่ได้) เปิดด้วยโปรแกรมของเครื่องจากไฟล์ชั่วคราว (`<temp>/rclonebrowser-view/<สุ่ม>/`)
- **แก้พร้อมกัน**: serve ที่มีรหัสผ่านทำให้ `RCLONE_CONFIG_PASS` (รหัสของ config ที่เข้ารหัส) และ login ของ remote control หายจาก
  environment — ตอนนี้ต่อจากของเดิม · test ตรวจว่าทั้งสองไปถึง rclone
- ยังไม่ได้: ไฟล์ชั่วคราวของหน้าต่างยังไม่ถูกลบ · ไม่มีปุ่มก่อน/ถัดไปในโฟลเดอร์ · ไม่ได้ลองกับของจริง (เก็บไว้ทดสอบรวม)

## serve โฟลเดอร์ให้โปรแกรมอื่น (2026-10-19)

- **core**: `RemoteOps::Serve(remote, path, ServeOptions)` → `rclone serve webdav|http|ftp|sftp` เป็นงานชนิดใหม่ `JobKind::Serve` ("serve")
  ทำงานจนกว่าจะหยุด · `ServeProtocols()` · `DefaultServePort()` (webdav 8081 · http 8080 · ftp 2121 · sftp 2022 — ไม่ใช้ 80/21/22 ที่ต้องมีสิทธิ์สูง) ·
  `ServeUrls()` ที่อยู่ที่เปิดได้ (127.0.0.1 + IPv4 ของเครื่องเมื่อ everyone)
- **พอร์ตของตัวเอง** ไม่ relay ผ่าน API แบบ stream: FTP/SFTP ไม่ใช่ HTTP และโปรแกรม WebDAV คาดหวัง server ของมันเอง
- **ความปลอดภัย**: ค่าเริ่มต้นฟังที่ 127.0.0.1 และ read only · ให้เครื่องอื่นเข้าได้ (`everyone`) **ต้องมี user + password** ·
  รหัสผ่านส่งทาง environment `RCLONE_PASS` (ใหม่: `RunningJob::setEnvironment` · `JobRegistry::start(..., environment)`) — ไม่อยู่ใน argv
  ที่ทุกคนบนเครื่องอ่านได้ ไม่อยู่ใน log/ประวัติ/`/jobs` · ชื่อ user ห้ามขึ้นต้นด้วย `-` · พอร์ตถูกใช้ → ปฏิเสธพร้อมเหตุผล
  (ตรวจทั้งเครื่องและ serve ของเราที่ rclone อาจยังไม่ได้จับพอร์ต) · sftp ไม่มี user → `--no-auth` (เฉพาะเครื่องนี้)
- **API**: `POST /remotes/{name}/serve` **ระดับ admin** (เปิดรีโหมดให้ใครก็ได้ที่เข้าถึงพอร์ต — มากกว่าที่ key ใดควรให้ได้) ·
  `/jobs` มี `serve` · `/system` มี `serveProtocols`
- **หน้าเว็บ**: ปุ่ม **Serve** ในแถบรีโหมด (โฟลเดอร์ที่เลือก หรือโฟลเดอร์ที่เปิดอยู่) · ฟอร์ม protocol/พอร์ต/อื่นเข้าได้/read only/user/password ·
  การ์ดงานแสดงที่อยู่ (host ของหน้าเว็บเองเมื่อ everyone) · ปุ่ม **Copy address**
- **หน้าต่าง**: **Serve…** ในเมนู Tools และเมนูคลิกขวา (`ServeDialog` ถามเหมือนหน้าเว็บ) · บอกที่อยู่หลังเริ่ม ·
  **การ์ดในแท็บ Jobs สำหรับ serve และ stream ที่หน้าเว็บสั่ง** (ก่อนหน้านี้ stream จากหน้าเว็บไม่ขึ้นในหน้าต่าง) — แสดงที่อยู่ แทนแถบความคืบหน้า ·
  "Stop all transfers" ไม่หยุด serve/stream (เหมือนที่ไม่หยุด mount)
- **ตรวจกับของจริง**: serve gdrive เป็น WebDAV ที่ 127.0.0.1:18082 read only + user/password → ไม่ login 401 · login ถูก 207 ·
  MKCOL 405 · รหัสไม่อยู่ใน command line ของ rclone และไม่อยู่ใน `/jobs` · Stop แล้วพอร์ตปิด ไม่มี rclone ค้าง ·
  ก่อนหน้านั้นยืนยันกับ rclone v1.73.1 ว่า `RCLONE_PASS` ใช้แทน `--pass` ได้จริง
- ยังไม่ได้: ลอง FTP/SFTP/everyone กับของจริง · ดูการ์ดและกล่อง Serve ในหน้าต่างด้วยตา · ค่า serve เก็บเป็น task ไม่ได้ · ใบรับรอง HTTPS (`--cert`)

## ความเร็วรวมและปรับความเร็วขณะรัน (2026-10-19)

- แต่ละงาน transfer มี remote control ของ rclone ตัวเองอยู่แล้ว (ใช้อ่านความคืบหน้า) — **`RcClient::setBandwidth`** สั่ง `core/bwlimit`
  ผ่านช่องทางเดียวกัน · `RunningJob::setBandwidth` · `bandwidth()` จำค่าที่ rclone บอกว่าตั้งแล้ว
- **API**: `POST /jobs/{id}/bandwidth {rate}` · `POST /bandwidth {rate}` (ทุกงานที่กำลังส่ง — **แต่ละงานได้ค่าเดียวกัน** 4 งานที่ 2M = 8M รวม) ·
  rate: `500k` `2M` `1.5G` `10M:1M` หรือ `off` · ระดับ control
- **ตัวเลขเพิ่มใน `/jobs`**: `speed` · `etaSeconds` · `percent` · `totalTransfers` · `bandwidth` · **`/system`**: `speed` (รวมทุกงาน) · `transferring`
- **หน้าเว็บ**: หัวหน้าแสดง ⇅ ความเร็วรวม · แท็บ Jobs มีบรรทัดรวม + ปุ่ม **Limit every running transfer…** ·
  การ์ดงานแสดงความเร็ว · เวลาที่เหลือ · ค่าที่จำกัด และปุ่ม **Speed…**
- **ตรวจกับของจริง**: ส่ง 30 MB ขึ้น gdrive (โฟลเดอร์ทดสอบ) · จำกัด 200k ระหว่างส่ง → rclone ตอบ `200Ki` และวัดได้ **191 KB/s** ·
  ปล่อยด้วย `/bandwidth off` → จบ finished · ลบโฟลเดอร์ทดสอบแล้ว
- **หน้าต่าง** (ทำแล้ว 2026-10-19): การ์ดงาน transfer มีปุ่ม **Speed…** ข้างปุ่ม copy · ถามค่าแบบเดียวกับหน้าเว็บ ·
  ตรวจค่าด้วย `RcClient::IsRate` ตัวเดียวกับ API · เมื่อจำกัดแล้วปุ่มแสดง `≤ 2M/s` · ค่าที่ตั้งจากหน้าเว็บก็ขึ้นบนการ์ด
  (`RunningJob::bandwidthChanged`) · ปุ่มหายเมื่องานจบ
- ค่าที่ปรับหายเมื่องานจบ (ไม่ใช่ของ task)

## อัปโหลดจากเครื่องที่เปิด browser (2026-10-19)

ตัวรับคำขอของ API อ่าน body ทั้งก้อนเข้าหน่วยความจำและจำกัด 1 MB — ใช้ส่งไฟล์ไม่ได้ จึงมีทางรับไฟล์แยก:

- **`ParseHttpHead`** — อ่านเฉพาะ request line กับ header · `read()` ดูหัวของคำขอก่อน body จะมาครบ ถ้าเป็น
  `POST /remotes/{name}/receive` จะสลับ connection นั้นเป็นโหมดรับไฟล์: **เขียนลงไฟล์พักทีละส่วนที่มาถึง** ไม่เก็บในหน่วยความจำ
- ตรวจครบก่อนรับ: token/key (ระดับ write) · รีโหมดมีจริง · ชื่อไฟล์ (`WhyNotAName`) · ต้องมี `Content-Length` (411) ·
  **ที่ว่างพอ** สำหรับไฟล์ + 64 MB (507)
- รับครบแล้ว → **`RemoteOps::UploadReceived`**: `rclone move <ไฟล์พัก> remote:folder` เป็นงาน transfer ปกติ (ความคืบหน้า · ประวัติ · Stop)
  ตอบ 202 พร้อม requestId · โฟลเดอร์พักถูกลบเมื่องานจบไม่ว่าผลเป็นอย่างไร · **ส่งค้างกลางทาง → ไฟล์พักถูกทิ้ง**
- ที่พัก: `RB_UPLOAD_STAGING` หรือ `<temp>/rclonebrowser-uploads` (ใน Docker คือ `/tmp` ของคอนเทนเนอร์)
- **หน้าเว็บ**: ปุ่ม **Upload from this computer** (เลือกหลายไฟล์) และ**ลากไฟล์หรือโฟลเดอร์มาวางบนรายการ** (โฟลเดอร์คงโครงสร้างเดิม) ·
  ส่งทีละไฟล์ · แถบความคืบหน้าต่อไฟล์ · เมื่องานย้ายขึ้นรีโหมดจบ รายการ refresh เอง · ปุ่ม Upload เดิมกลายเป็น "จากเครื่องที่โปรแกรมรัน พร้อมตัวเลือกครบ"
- **ตรวจกับของจริง**: ส่ง 20 MB สุ่มขึ้น gdrive (โฟลเดอร์ทดสอบ) — รับใน 0.7 วินาที · **หน่วยความจำโปรแกรม 127 → 128 MB** ·
  งาน finished · ดึงกลับมา**ไบต์ตรงกัน** (SHA-256) · ไม่มีไฟล์พักค้าง · ลบโฟลเดอร์ทดสอบแล้ว
- ⚠ ยังไม่ได้ลองปุ่ม/การลากวางใน browser ด้วยตา · ไฟล์ต้องมีที่ว่างบนเครื่องที่โปรแกรมรันระหว่างส่ง ·
  ไม่มีการส่งต่อเมื่อขาด (ต้องส่งใหม่ทั้งไฟล์) · หน้าต่างไม่ต้องมี (ลากไฟล์ในเครื่องมาวางได้อยู่แล้ว)

1. **ตั้งค่ารีโหมดจากหน้าเว็บ** (5 จาก 8) — มีแผนแยก `REMOTE-CONFIG-UI.md` แล้วแต่ยังไม่เริ่ม · สำคัญที่สุดสำหรับโหมด web ของ Docker เพราะตอนนี้ต้องแก้ rclone.conf เอง
2. **อัปโหลดจากเครื่องที่เปิด browser** (ลากไฟล์มาวาง) — ของเราอัปโหลดได้เฉพาะจากโฟลเดอร์ฝั่งเซิร์ฟเวอร์
3. **dashboard / ความเร็วรวม และปรับ bandwidth ขณะรัน** (rc `core/bwlimit`)
4. **serve ทั้งรีโหมด** WebDAV/SFTP/FTP — ของเรามี stream (serve http) ของไฟล์/โฟลเดอร์เดียว
5. **ดูไฟล์ในตัว** ภาพ · PDF · ข้อความ — ของเรามีแค่เครื่องเล่นวิดีโอ/เสียง
6. **การแจ้งเตือน** (tray · webhook) — ของเรามี A6 webhook ในแผน
7. **sync สองทาง (bisync)** และ **ตัวช่วยสำรองข้อมูล**
8. **เลือกหลายรายการ · เมนูคลิกขวา** — อยู่ในรายการของเราแล้ว
9. หลายภาษา · เฝ้าโฟลเดอร์

**สิ่งที่เรามีและคนอื่นแทบไม่มี**: คิวที่เรียงได้ · task ที่บันทึกพร้อมตัวเลือกครบ · ตารางเวลา cron/daily ที่ทำงานโดยไม่ต้องเปิดหน้าต่าง ·
หน้าต่างกับหน้าเว็บที่ซิงก์กัน · API ของตัวเองพร้อม OpenAPI และ key แบบจำกัดสิทธิ์ · ประวัติการรันพร้อมขนาด ·
ขอบเขตโฟลเดอร์ (`RB_LOCAL_ROOTS`) และรายชื่อ flag ต้องห้าม

## ที่เจอระหว่างทาง

จดไว้ ยังไม่ได้ทำ เรียงตามที่เจอ

- **เวลาใน endpoint เดิมยังไม่มี offset** — `lastUpload.startedAt` เป็น `…+07:00` แล้ว
  แต่ `/jobs` และ `/history` ยังส่งแบบไม่มี offset · อยู่ใน A2 อยู่แล้ว ต้องทำให้เหมือนกันทั้งหมด
- **`GetRcloneCmd` อ่านเกินท้ายรายการ** เมื่อคำสั่งมีอาร์กิวเมนต์เดียวหลังชื่อคำสั่ง — มันสมมติว่าทุกคำสั่งคือ
  "verb source dest" · ไม่เคยมีอะไรไปเหยียบจนสร้างโฟลเดอร์ผ่าน registry · **แก้แล้ว** พร้อม test
  (ใน release build มันคือการอ่านหน่วยความจำมั่ว ไม่ใช่ assertion)
- ~~Upload/Download ของหน้าเว็บมีตัวเลือกแค่ dry run~~ — **ทำแล้ว** ดู "ฟอร์ม Transfer และการเขียน task"
- **แท็บ Remotes เป็นหน้าแรก และรีโหมดมีไอคอนตามชนิด** (2026-10-12) — ใช้รูปชุดเดียวกับหน้าต่าง
  เสิร์ฟที่ `/icons/remote/<ชนิด>[_inv].png` โดยไม่ต้องมี token (รูป `<img>` ส่ง header ไม่ได้ และรูปไม่ใช่ข้อมูลของเครื่องนี้)
  ชื่อถูกจำกัดเป็น `a-z 0-9 _` · ชนิดที่ไม่มีรูปได้รูป unknown · รูปอยู่ใน resource ของหน้าต่าง ไม่ใช่ของ core —
  **build ที่ไม่มีหน้าต่างจะไม่มีรูป** (ได้ 404 และหน้าเว็บซ่อนกรอบรูป) ถ้าจะทำอิมเมจ web-only ขนาดเล็กต้องย้ายรูปมา core
  มีรูป 38 ชนิด — ชนิดใหม่ๆ ของ rclone (pikpak · protondrive ฯลฯ) ยังไม่มีรูป ได้ unknown
- **task ชนิด mount แก้จากหน้าเว็บไม่ได้** — แสดง · รัน · ลบได้ แต่ไม่มีปุ่ม Edit เพราะ `TaskJson::Read`
  ไม่เขียนช่องของ mount (รวม `mountScript` ซึ่งคือการรันโปรแกรมตรงๆ) ยังต้องแก้ในหน้าต่าง
- **ลบ task แล้วตารางเวลาที่ชี้ไปยัง task นั้นยังอยู่** — เป็นแบบเดียวกับที่หน้าต่างทำมาตลอด
  หน้าเว็บเตือนในกล่องยืนยัน แต่ควรมีที่บอกว่าตารางเวลาไหนกำพร้า (ทำตอน A5 ข้อ 1)
- **ค่าเริ่มต้นของฟอร์มอยู่สองที่** — `transfer_dialog.ui` กับ `TaskJson::Defaults` (transfers 4 · checkers 8 ·
  timeout 60/300 · retries 3/10) ถ้าเปลี่ยนต้องเปลี่ยนทั้งคู่ ควรให้หน้าต่างอ่านจาก core ด้วย
- **`POST …/upload` · `…/download` แบบสั้นยังอยู่ใน API** แต่หน้าเว็บไม่ได้ใช้แล้ว — เก็บไว้ให้ระบบอื่น
  ที่อยากสั่งส่งไฟล์โดยไม่สร้าง task
- **ฟอร์มบนเว็บ**: ผู้ใช้ลองแล้ว (ภาพหน้าจอ 2026-10-12) เจอสองเรื่อง — ช่อง path พิมพ์มั่วได้ และ Extra options
  เป็นกล่องข้อความ — แก้แล้วทั้งคู่ · ปุ่มท้ายฟอร์มถูกตัดเมื่อจอเตี้ย แก้แล้ว (เฉพาะส่วนแท็บที่หดได้)
- **path ที่ไม่มีอยู่และโฟลเดอร์แม่ก็ไม่มี ได้ 403 `outside_roots`** แม้บนเครื่องที่ไม่ได้จำกัด — เป็นผลของ
  "อยู่นอกกับไม่มีอยู่ได้คำตอบเดียวกัน" ข้อความจึงชวนงงบนเครื่องโต๊ะ ควรแยกคำตอบเมื่อไม่ได้จำกัด
- **Include / Exclude / Filter เป็นรายการใส่ทีละค่าแล้ว** (2026-10-12) — Filter มีตัวเลือก + / − และย้ายลำดับได้
  แต่**ตัว pattern ยังไม่ถูกตรวจ** ว่า rclone อ่านออกไหม · สิ่งที่บันทึกยังเป็นข้อความบรรทัดละค่าเหมือนที่หน้าต่างเก็บ
- **Bandwidth · Min size · Min/Max age เป็นตัวเลข + ตัวเลือกหน่วยแล้ว** (2026-10-12) — ค่าที่หน้าต่างยอมแต่ไม่ใช่
  "เลขหนึ่งตัวกับหน่วย" (ตารางเวลาของ bwlimit · `1h30m` · วันที่) ถูกเก็บไว้ตามเดิมและบอกใต้ช่อง
  ตั้งค่าแบบนั้นจากเว็บยังไม่ได้ ต้องทำในหน้าต่าง
- **หน้าต่างยังพิมพ์ flag อิสระ** — ตั้งใจ แต่แปลว่า task ที่สร้างในหน้าต่างอาจมี flag ที่หน้าเว็บแสดงเป็นสีแดง
  และแก้ `extra` ของมันผ่านเว็บไม่ได้จนกว่าจะเอา flag นั้นออก
- **test ลิงก์ออกนอก root ถูกข้ามบน Windows** (สร้าง symlink จริงต้องมีสิทธิ์พิเศษ) — ตรวจด้วยมือในคอนเทนเนอร์แล้ว
  แต่ CI ควรรัน test ชุดนี้บน Linux ด้วย
- **`/media` ในอิมเมจมีโฟลเดอร์ของ Alpine ติดมา** (`cdrom` `floppy` `usb`) โผล่ในตัวเลือก ควรลบตอน build
- **ตัวกรองผล build ของผมแคบเกินไป** — ดูแค่ `error C` กับ `error LNK` ข้อผิดพลาดของ moc
  (`Not a signal or slot declaration`) จึงหลุด: ตัวแปรสมาชิกถูกใส่ในส่วน `slots:` ของ header
  ตัวโปรแกรมไม่ถูก build ใหม่ แต่ test ผ่านหมดเพราะ test ไม่ได้ลิงก์หน้าต่าง · จับได้เพราะลองเรียก
  endpoint ใหม่บนตัวจริงแล้วได้ 404 · **ต้องมีขั้นตรวจว่าตัวโปรแกรมถูก build จริง** ก่อนถือว่ารอบนั้นผ่าน
- **Mount จากหน้าเว็บมีตัวเลือกแค่ read-only กับ cache** — หน้าต่างมี volume name · script หลัง mount ·
  โหมดไดรฟ์ของ Windows · flag เพิ่ม
- **mount ที่เริ่มจาก task ไม่ได้ตัวเลือก mount จากตั้งค่า** (`Settings/mount`) — `addNewMount()` ของหน้าต่าง
  และ `RemoteOps::Mount` ใส่ให้ แต่ `StartTask()` ไม่ใส่ task แบบ mount ที่รันจากคิว ตารางเวลา หรือ API
  จึงได้คำสั่งต่างจากที่กดรันในหน้าต่าง
- ~~Stream ยังไม่ได้ทำ~~ — **ทำแล้ว** (2026-10-12/18) ดู "Stream"
- **Check ของหน้าเว็บเทียบได้แค่รีโหมดกับรีโหมด** — หน้าต่างเทียบกับโฟลเดอร์ในเครื่องได้
  ต้องรอ API เดินดูโฟลเดอร์ฝั่งเครื่อง (ตัวเดียวกับที่ Upload/Download ต้องใช้)
- **กล่อง Check ของหน้าต่างยังประกอบคำสั่งเอง** (รับ path ที่พิมพ์ + flag เพิ่ม + cryptcheck)
  ผ่าน registry แล้วแต่ยังไม่ผ่าน `RemoteOps::Check` · Export ของหน้าต่างก็ยังมีตัวกรองมากกว่า
  (min-size · min-age · max-age · exclude) ที่ API ยังไม่รับ
- **Check และ Export ที่ใช้เวลานานถือ connection ค้าง** — เหมือน Size · ถ้าจะให้รันเบื้องหลังได้
  ต้องเก็บ output ของงานไว้ให้มาอ่านทีหลัง ซึ่งตอนนี้มีแต่ไฟล์ log (และปิดได้ในตั้งค่า)
- **การ์ดรีโหมดไม่บอกว่ามีการคัดลอก/ย้ายบนรีโหมดครั้งล่าสุดเมื่อไร** — ตอนนี้งานพวกนี้ไม่ขึ้นที่ไหน
  บนการ์ดเลย (อยู่แต่ใน History) อาจเพิ่มบรรทัด "แก้ไขครั้งล่าสุด" ที่รวมทุกอย่างที่เขียนลงรีโหมด
- **หน้าต่างคัดลอกข้ามรีโหมดไม่ได้** — กล่องเลือกปลายทางของหน้าต่างแสดงแต่รีโหมดเดียวกัน
  หน้าเว็บทำได้แล้ว ตามกติกาข้อ 1 หน้าต่างควรทำได้ด้วย (กลับด้านจากปกติ)
- **Copy/Move ของหน้าเว็บมีแค่ dry run** — หน้าต่างมีตัวเลือกเพิ่ม: create-empty-src-dirs ·
  delete-empty-src-dirs · no-traverse · verbose · flag เพิ่ม
- **หน้าเว็บไม่รู้ว่า backend ทำอะไรได้** — หน้าต่างปิดปุ่ม Link · Cleanup · Dedupe ตามความสามารถ
  ของ backend (`rclone_capabilities`) หน้าเว็บเปิดทุกปุ่มแล้วให้ rclone ปฏิเสธเอง
  ต้องมี `GET /remotes/{name}` ที่บอกความสามารถ แล้วให้หน้าเว็บปิดปุ่มแบบเดียวกัน (อยู่ใน A1 แล้ว)
- **แถบเครื่องมือของหน้าเว็บมี 10 ปุ่มเรียงกัน** — ควรจัดกลุ่ม หรือทำเมนูคลิกขวาแบบหน้าต่าง
- **output ของงานถูกตัดช่องว่างหัวบรรทัด** — `rclone tree` จึงเสียรูป: กิ่งสุดท้ายของแต่ละชั้นขึ้นต้นด้วย
  ช่องว่าง และช่องว่างคือสิ่งเดียวที่บอกว่าโฟลเดอร์ไหนอยู่ในโฟลเดอร์ไหน หน้าต่างเป็นแบบนี้มาตั้งแต่ย้าย
  เครื่องมือเข้า registry · **แก้แล้ว** (ตัดแค่ท้ายบรรทัด) พร้อม test
- **Size ในหน้าเว็บทำได้ทีละรายการ** — หน้าต่างเลือกหลายรายการแล้วรวมขนาดได้ (ใช้ `--filter`)
- **คำถามที่ใช้เวลานานไม่มีปุ่มยกเลิกในหน้าเว็บ** — ปิดกล่องแล้วงานยังวิ่งต่อจนจบ
  (จะหยุดเมื่อปิดแท็บเท่านั้น) ควรมีปุ่ม Cancel ที่หยุดงานจริง
- **Info น่าจะอยู่บนการ์ดรีโหมดเลย** — ตอนนี้ต้องกดถาม ถ้าเก็บผลล่าสุดไว้ก็แสดงโควตาใต้ชื่อรีโหมดได้
  เหมือนบรรทัด "อัปโหลดครั้งล่าสุด"
- **หน้าเว็บเลือกได้ทีละแถว** — หน้าต่างเลือกหลายรายการแล้วลบพร้อมกันได้ หน้าเว็บยังต้องลบทีละอัน
  ต้องเพิ่ม Ctrl/Shift-คลิก และ API ที่รับหลาย path ในคำขอเดียว · และยังไม่มีเมนูคลิกขวาแบบหน้าต่าง
- **`prompt()` / `confirm()` ของ browser** ใช้ถามชื่อและยืนยันการลบ ใช้ได้แต่หน้าตาเป็นของ browser
  ควรเป็นกล่องของหน้าเว็บเอง โดยเฉพาะกล่องยืนยันการลบ
- **กล่องลบของหน้าต่างรันหลายงานพร้อมกัน** (ตามเดิม) — ตอนนี้แต่ละรายการเป็นหนึ่งแถวในประวัติ
  ลบ 500 ไฟล์ = 500 แถว อาจต้องรวมเป็นงานเดียว
- **ผลลัพธ์ของเครื่องมือ (Size · Info · DirTree) ยังไม่มีที่แสดงในหน้าเว็บ** — ต้องมีแผงผลลัพธ์
  ที่อ่าน output ของงาน ซึ่งคือ `/jobs/{id}/log` ที่มีอยู่แล้ว
- **เหตุการณ์ `job` ถูกส่งสำหรับงานทุกชนิด** รวม mkdir — แท็บ Jobs ของหน้าเว็บจึงมีการ์ดของงานที่ไม่ใช่
  transfer โผล่มา ต้องตัดสินว่าจะแสดงหรือกรอง (หน้าต่างแสดงการ์ดเฉพาะ transfer)
- **ไม่มีอะไรจดคำสั่งที่งานรันจริง** — ถ้าประวัติเก็บ command line (ฉบับปิดความลับ) ไว้ต่อแถว
  คำถามอย่าง "รอบนี้ dry run ไหม ใช้ flag อะไร" จะตอบได้ย้อนหลังโดยไม่ต้องอนุมาน
- **test ที่ไม่ได้เป็น slot ไม่มีอะไรเตือน** — ควรมีตัวตรวจใน `scripts/` ที่ล้ม build
  เมื่อพบ `void xxx()` ของ test อยู่นอก `private slots:`
- **ไม่รู้ว่าอัปโหลดสำเร็จครั้งล่าสุดเมื่อไร** — ตอนนี้บอกครั้งล่าสุดไม่ว่าผลเป็นอะไร
  OneDrive ที่ token หมดอายุจึงขึ้นแต่ครั้งที่ล้ม คำถามที่คนอยากรู้จริงอาจเป็น "ครั้งสุดท้ายที่สำเร็จ"
  — เพิ่ม `lastSuccessfulUpload` ได้จาก query เดียวกัน
- **รายละเอียดรีโหมดที่ยังเพิ่มได้** — โควตา (`rclone about`) · จำนวน task และตารางเวลาที่ชี้มา ·
  ปริมาณที่ส่งรวม · กำลังมีงานวิ่งอยู่ไหม
- **ป้ายใต้รีโหมดในหน้าต่างปรับขนาดช่องเฉพาะแบบ tiles** — แบบ `list` และ `longlist` ต่อท้ายบรรทัดเดียว
  ยังไม่ได้ดูด้วยตาว่าพอดีไหม
- **หน้าเว็บแท็บ Remotes ไม่มีเหตุการณ์ของตัวเอง** — ได้ข้อมูลใหม่เมื่อมีเหตุการณ์ `job`
  หรือ refresh รอบถัดไป (สูงสุด 30 วิ) ใช้ได้ แต่ควรมีเหตุการณ์ `remote`

สองงานนี้เป็นงานเดียวกันมองจากสองด้าน: **หน้าเว็บแสดงได้เท่าที่ API ส่งออกมา**
ทุกอย่างที่อยากให้หน้าเว็บแสดงเพิ่ม ต้องเพิ่มใน API ก่อน และพอเพิ่มแล้วระบบอื่นก็ได้ใช้ด้วย
จึงเรียงงานตาม API แล้วให้หน้าเว็บเป็นผู้ใช้รายแรกของมัน

## สภาพตอนนี้

**core รู้มากกว่าที่ API ส่งออก และ API ส่งออกมากกว่าที่หน้าเว็บแสดง**

| เรื่อง | core มี | API ส่ง | หน้าเว็บแสดง |
|---|---|---|---|
| ความคืบหน้างาน | ไบต์ · ความเร็ว · ETA · ไฟล์ x/y · checks x/y · ลบ/เปลี่ยนชื่อ · เฟส · **รายไฟล์ที่กำลังส่ง** | ไบต์ · จำนวนไฟล์ · error · เวลา | หลอด + 4 ตัวเลข |
| ประวัติ | ต้นทาง · ปลายทาง · คำสั่ง · exit code · ไฟล์ · error · ขนาด log | ชื่อ · ชนิด · ผล · ไบต์ · เวลา | ตารางแถวเดียว |
| task | ~45 ช่อง (operation · ตัวกรอง · bandwidth · retries · flag เพิ่ม …) | 5 ช่อง | ชื่อ + ต้นทาง/ปลายทาง |
| ตารางเวลา | วัน/เวลา หรือ cron · โหมดรัน · ผลครั้งล่าสุด | บางส่วน | ชื่อ · ครั้งถัดไป |
| รีโหมด | ชนิด · ความสามารถของ backend | ชื่อ + ชนิด | ปุ่ม + รายการไฟล์ |

**การเขียนมีแค่คำสั่ง** — run · enqueue · stop · หยุด/เดินคิว · shutdown · ตั้งรหัสผ่าน
สร้าง/แก้ task กับตารางเวลา ยังต้องทำในหน้าต่าง

**ไม่มีเอกสารที่เครื่องอ่านได้** — `HTTP-API.md` เขียนให้คนอ่าน ระบบอื่นต้องเดาเอาจากตัวอย่าง

## ส่วน A — API

### A1 · ส่งออกสิ่งที่ core รู้อยู่แล้ว (อ่านอย่างเดียว)

ไม่มีความเสี่ยง ไม่ต้องตัดสินใจอะไร เป็นการเติมช่องให้ครบ

- `GET /jobs` · `/jobs/{id}` — เพิ่ม `speed` `etaSeconds` `percent` `checks/totalChecks`
  `transfers/totalTransfers` `deletes` `renames` `phase` และ **`transferring[]`** (รายไฟล์)
- `GET /history` — เพิ่ม `source` `dest` `info` `totalBytes` `transfers` `errors` `logBytes` `taskId`
  · ตัวกรอง `?taskId=` `?state=` `?kind=` · **แบ่งหน้า** `?before=<requestId>&limit=`
- `GET /history/{id}` — แถวเดียวพร้อมคำสั่งที่รัน (ฉบับปิดความลับ)
- `GET /tasks/{id}` — task เต็ม เป็น **schema ที่มีชื่อช่องชัด** ไม่ใช่ dump ของ `JobOptions`
- `GET /schedules/{id}` — วัน/เวลา · cron · โหมดรัน · ผลครั้งล่าสุด
- `GET /remotes/{name}` — ความสามารถของ backend · `GET /remotes/{name}/about` — โควตา
- `GET /system` — เพิ่มเวอร์ชันโปรแกรม · โหมด (window/daemon) · เวลาที่รันมา · repo ของ rclone

### A2 · รูปแบบที่ต้องตกลงก่อนจะมีคนอื่นมาใช้

พอมีระบบอื่นมาพึ่ง การเปลี่ยนรูปแบบทีหลังคือการทำของคนอื่นพัง จึงต้องนิ่งก่อนเปิด

| เรื่อง | ข้อเสนอ |
|---|---|
| ข้อผิดพลาด | รูปเดียวทุกที่: `{"error": "...", "code": "task_already_running"}` — `code` คือสิ่งที่เครื่องใช้ตัดสิน ข้อความคือสิ่งที่คนอ่าน |
| เวลา | ISO 8601 มี offset เสมอ (`2026-10-12T10:52:36+07:00`) ตอนนี้ส่งแบบไม่มี offset |
| ขนาด | ไบต์เป็นตัวเลขเสมอ ไม่ส่งข้อความ "1.2 GiB" |
| รายการยาว | `{"items": [...], "next": "<cursor>"}` แทน array เปล่า เพื่อให้แบ่งหน้าได้โดยไม่ต้องเปลี่ยนรูป |
| เวอร์ชัน | `/api/v1` **เพิ่มได้ ห้ามเปลี่ยนความหมาย ห้ามเอาออก** ถ้าต้องแตกหักคือ `/api/v2` |
| ช่องที่ไม่รู้จัก | ผู้ใช้ต้องไม่พังเมื่อเจอช่องใหม่ เขียนไว้ในเอกสาร |

> ข้อ "รายการยาว" **เปลี่ยนรูปของ endpoint ที่มีอยู่** (จาก array เป็น object)
> หน้าเว็บของเราเป็นผู้ใช้รายเดียวตอนนี้ จึงเป็นจังหวะเดียวที่เปลี่ยนได้โดยไม่มีใครเดือดร้อน

### A3 · OpenAPI — สร้างจากตารางเส้นทาง ไม่เขียนด้วยมือ — **ทำแล้ว (2026-10-18)** ดู "เอกสาร API อัตโนมัติ"

**ตัดสินแล้ว:** เอกสารสร้างอัตโนมัติ และแสดงบนหน้าเว็บ

ตอนนี้เส้นทางของ API เป็น `if (path == …)` เรียงกันในฟังก์ชันเดียว ไม่มีที่ไหนที่ "รู้" ว่ามี endpoint
อะไรบ้าง สเปกจึงสร้างเองไม่ได้ ต้องเปลี่ยนเป็น **ตารางเส้นทาง** ก่อน:

```cpp
{ "GET", "/remotes/{name}/ls", Scope::Read,
  "รายการไฟล์ในโฟลเดอร์ของรีโหมด",
  params  = { path("name"), query("path"), query("limit", Integer) },
  returns = Schema::DirectoryListing,
  handler = &ApiServer::listRemote }
```

**ตารางเดียวนี้ใช้ทำสามอย่าง**: จับคู่คำขอกับ handler · บอกสิทธิ์ที่ต้องมี (A4) ·
และ**สร้าง `GET /api/v1/openapi.json`** — สเปกจึงเพี้ยนจากของจริงไม่ได้โดยโครงสร้าง
เพราะ endpoint ที่ไม่อยู่ในตารางคือ endpoint ที่ไม่มีอยู่

- schema ของคำตอบประกาศครั้งเดียว (`Schema::Job` · `Schema::Task` …) คู่กับตัวสร้าง JSON ของชนิดนั้น
  · มี **test ที่เรียกทุก endpoint แล้วตรวจคำตอบกับ schema ที่ประกาศไว้** — นี่คือส่วนเดียวที่ยังเพี้ยนได้
  (ประกาศว่าส่ง `speed` แต่ลืมใส่) และ test นี้จับได้
- **หน้าเอกสารบนเว็บ** (`#/api`) อ่าน `openapi.json` แล้ววาด: endpoint จัดกลุ่ม · พารามิเตอร์ ·
  รูปคำตอบ · ตัวอย่าง · **ปุ่มลองเรียก**ด้วย session ที่ล็อกอินอยู่ · เขียนตัวแสดงเอง
  ไม่ฝัง Swagger UI (กติกาเดิม: ไม่มีของนอกใน binary)
- ไฟล์สเปกเสิร์ฟ**โดยไม่ต้องใช้ token** — บอกรูปร่างของ API ไม่ได้บอกข้อมูลของใคร
  เครื่องมือสร้าง client และระบบอื่นใช้ได้ทันที
- SSE `/events` อยู่ในตารางเดียวกัน พร้อมรายการชนิดเหตุการณ์กับ payload

### A4 · กุญแจสำหรับระบบอื่น — **ทำแล้ว (2026-10-18)** ดู "API key แบบจำกัดสิทธิ์"

ตอนนี้มี token เดียวที่ทำได้ทุกอย่าง **ให้ระบบอื่นไปใช้คือให้กุญแจบ้านทั้งดอก**
และเพิกถอนทีละรายไม่ได้ — เปลี่ยน token ทีเดียวทุกระบบหลุดหมด

ข้อเสนอ: **API key มีชื่อ มีสิทธิ์ เพิกถอนได้ทีละดอก**

| สิทธิ์ | ทำอะไรได้ |
|---|---|
| `read` | GET ทุกอย่าง · events · log |
| `control` | + run · enqueue · stop · หยุด/เดินคิว |
| `write` | + สร้าง/แก้/ลบ task และตารางเวลา |
| `admin` | + shutdown · จัดการ key · รหัสผ่าน (token เดิมและ session ของ admin คือระดับนี้) |

- เก็บแบบ hash เหมือนรหัสผ่าน · แสดงตัว key **ครั้งเดียว**ตอนสร้าง
- แต่ละ key จำ: ชื่อ · สิทธิ์ · สร้างเมื่อไร · **ใช้ล่าสุดเมื่อไร**
- ประวัติงานบอกว่า key ไหนสั่ง (`startedBy: "api:sonarr"`) แทน `api` เฉยๆ
- จัดการในหน้าเว็บ (แท็บ Settings) และผ่าน API ด้วยสิทธิ์ `admin`

### A5 · การเขียน

เรียงจากเสี่ยงน้อยไปมาก

1. ~~ตารางเวลา~~ — **ทำแล้ว** (2026-10-12) `POST/PUT/DELETE /schedules` · `POST /schedules/{id}/enable|disable` · `POST /scheduler/start|pause`
   ไม่เสี่ยง: ตารางเวลาชี้ไปที่ task ที่มีอยู่แล้วเท่านั้น
2. ~~คิว~~ — **ทำแล้ว** (2026-10-18) `POST /queue/{id}/move` (`to`: เลขตำแหน่ง หรือ up · down · top · bottom) · `POST /queue/clear`
3. **task** — `POST/PUT/DELETE /tasks` ← **จุดเสี่ยง**

**ต้องตัดสินใจ (2): task เขียนผ่าน API ได้แค่ไหน**

task มีช่อง `extra` (flag เพิ่มของ rclone) และ `mountScript` — **การเขียน task จึงเท่ากับการเขียน
command line** key ที่หลุดจะกลายเป็น "รันอะไรก็ได้บนเครื่องนี้" นี่คือเหตุผลที่ยังไม่เปิดมาตลอด

| ทาง | ได้อะไร | เสี่ยงอะไร |
|---|---|---|
| **ช่องที่มีโครงสร้างเท่านั้น** (แนะนำ) | สร้าง/แก้ task ได้: ต้นทาง · ปลายทาง · operation · ตัวกรอง · bandwidth · retries ฯลฯ ทุกช่องตรวจชนิดและช่วงค่า | `extra` และ `mountScript` **อ่านได้ เขียนไม่ได้** — task ที่ต้องใช้ flag พิเศษยังต้องตั้งในหน้าต่าง |
| + `extra` แบบรายชื่อที่อนุญาต | flag เพิ่มได้ ถ้าอยู่ในรายชื่อ flag ที่ rclone รู้จัก (`rclone_flags` มีอยู่แล้ว) และไม่อยู่ในรายชื่อต้องห้าม | รายชื่อต้องห้ามต้องถูกทุกตัว (`--config` · `--rc-*` · `--password-command` · `--*-command` · backend ที่มี command) พลาดตัวเดียวคือรูรั่ว |
| เปิดหมด หลังสวิตช์ | ทำได้ทุกอย่างเท่าหน้าต่าง ถ้าเปิด `apiAllowRawFlags` | คนเปิดทิ้งไว้แล้วลืม |

ไม่ว่าทางไหน **ต้นทาง/ปลายทางที่เป็น path ในเครื่อง** ก็เป็นคำถามเดียวกันในขนาดเล็กกว่า:
key ที่มีสิทธิ์ `write` สั่ง copy `/etc` ไปขึ้นรีโหมดได้ ใน Docker ขอบเขตคือ volume ที่ mount เข้ามา
บนเครื่องจริงคือทั้งเครื่อง — ข้อเสนอคือ**ตั้งรายชื่อโฟลเดอร์ที่ API ใช้เป็นต้นทาง/ปลายทางได้**
(`apiAllowedRoots`) ว่างแปลว่าไม่จำกัด และค่าเริ่มต้นใน Docker คือ `/media`

### A6 · ให้ระบบอื่นรู้เองโดยไม่ต้องถาม (ทีหลัง)

SSE ต้องมีคนเปิดสายค้างไว้ ระบบอย่าง Sonarr หรือสคริปต์ทั่วไปอยากได้ **webhook**: งานจบแล้วยิง POST
ไปหา URL ที่ตั้งไว้ · ไม่อยู่ในรอบนี้ แต่ออกแบบชนิดเหตุการณ์ใน A3 ให้ใช้ payload เดียวกันได้

| **Schedules** | "ทุกวันจันทร์–ศุกร์ 06:30" แทนรหัส · นับถอยหลัง · ผลครั้งล่าสุด · สวิตช์เปิด/ปิด · สร้าง/แก้ | A1 A5 |
| **Queue** | ลากเรียงลำดับ · ล้างคิว | A5 |
| **Remotes** | ความสามารถของ backend · โควตา · เรียงตามชื่อ/ขนาด/เวลา · กรองชื่อ · ขนาดโฟลเดอร์ | A1 |
| **Settings** (ใหม่) | เวอร์ชัน · โหมด · rclone ที่ใช้ · **จัดการ API key** · ลิงก์ไปหน้าเอกสาร API | A4 |

**โครงที่ต้องเปลี่ยน**

- **ที่อยู่ของแต่ละหน้า** (`#/history/{id}`) — ตอนนี้ refresh แล้วกลับไปแท็บแรก และส่งลิงก์ไปหางานที่ล้มให้ใครไม่ได้

- **จอแคบ** — ตารางกว้างล้นบนมือถือ แผงรายละเอียดต้องเป็นเต็มจอ
